# Anti-AI Web Design｜去 AI 模板感的网站设计 Skill

## 目标与适用范围

让网页看起来像经过品牌策略、艺术指导、排版推敲和真实前端实现的作品，而不是通用 AI Landing Page 拼装。

适用于：品牌官网、数字工作室、设计师作品集、艺术画册、概念产品发布页、视觉实验页面，以及 **SaaS、AI 产品后台、管理系统、分析报表、B 端工作台**。可用于从零设计、改造既有页面、撰写生成提示词、实现 HTML/CSS/React/Vue 前端、视觉走查。

**两条设计路线必须分开：**

- **表达型页面（Editorial / Marketing）**：允许超大字、视觉叠层、不对称、画册留白、差异化动效；追求品牌记忆点。
- **任务型界面（Product / Dashboard）**：追求可扫描的数据层级、语义色、操作效率、安静的容器、稳定的信息架构；不为“艺术感”随意改变业务工作流。

同一个产品可同时存在两种路线，例如官网用编辑式首屏，登录后的后台用严谨的应用外壳。

**核心判据：** 不是“黑底 + 大字 + 渐变”就算去 AI 味；必须同时具备独特的内容结构、明确的视觉焦点、可信的设计细节和可用的产品体验。

**使用原则：** 尊重品牌和用户已提供的素材、文案、配色、组件库及技术栈。不得为了“酷”牺牲阅读、无障碍、转化与性能。高信息密度的后台与工具界面不应强行套用展示型首页风格。

## 一、先做设计决策，不要先堆组件

1. 识别：这个页面的**品牌身份、目标用户、页面任务、唯一最重要内容、已有视觉资产、技术约束**。
2. 用一句话确定艺术方向，例如「印刷画册式」「前卫设计师画廊」「精密硬件发布」「强对比数字工作室」。
3. 为首屏确定**一个**主视觉重心（巨字 / 图片 / 产品 / 动态画廊），而不是让所有元素争夺注意力。
4. **先做页面类型分流**：如果是品牌/展示页，从「四种首屏配方」选择一个主方向、从「六种布局语法」选择一个主布局（至多一个辅助布局）；如果是业务后台，优先使用第五节的产品 UI 改造准则。**不得把六种技巧全部塞进同一页，也不得强行把后台改成创意作品集。**
5. 先做信息层级与线框，再定字体、网格、色彩、素材、运动，最后编码和视觉复查。
6. 素材不足时，用合理的设计性占位方案并说明假设；**不得编造品牌背书、客户 LOGO、指标、奖项、作品和虚假内容**。

## 二、十条全局「去 AI 味」设计规则

### R1. 用一个清晰的视觉主张替代平均用力

首屏应该在 3 秒内形成记忆点：一组穿插人物的字标、一个孤立的竖版艺术品、一个被精确构图的倾斜产品，或一个圆形的作品窗口。其他元素降低存在感，服务主角。

### R2. 字体就是构图，不只是内容

- 标题可大胆放大、换行、裁切边缘、部分遮挡或穿越图像，但**关键信息必须可读**。
- 建立悬殊但有序的层级：display / heading / body / microcopy；尽量不用全站相同字号、相同字重。
- 巨字搭配短行说明、极小编号、字距拉开的标签、精确对齐的元数据；不是所有文字都加粗。
- 中英文字体考虑笔画、字面率与混排；像素字体只用于适合的技术或复古概念，不用于所有正文。

### R3. 用编辑设计（Editorial Design）网格控制秩序

将页面视作跨页杂志或高端海报：使用明确基线、栏目、边界、横竖细线、编号、图注和元数据。可以打破网格，但偏离必须有意图；避免所有对象机械居中。

### R4. 把留白当成视觉元素

大面积深色或浅色空域不是“缺内容”；用它建立节奏、压住细节，并凸显唯一的焦点。避免在每一个空位塞统计块、装饰球、功能卡或 CTA。

### R5. 让图像成为叙事主体

优先使用真实作品、原创图像、产品渲染、摄影、手绘、视频画面；构图、裁切、角度与光线应与品牌调性一致。不要用泛用 3D 浮球、无意义 AI 人像、随机 Unsplash 图或混乱的视觉资产。

### R6. 强对比、有限色、克制发光

以黑/炭灰/暖白等中性色承担大部分面积，按品牌需要使用少量强调色。展示页可以有一处明确的舞台光；**业务后台不要整页紫蓝大渐变、发光卡片、彩色阴影、霓虹边框或高饱和选中态**。增长、异常、警告等状态色与品牌强调色分离，颜色必须有语义，不以“炫”为目的。

### R7. 主动制造受控的不对称

采用偏置排版、交错栏、错位图片、局部叠层、不同尺寸卡片。错位必须形成路径和层级，而不是随机 absolute 定位。结构上仍保持一致的对齐、间距和可预期阅读顺序。

### R8. 微细节决定真实感

展示页可使用低调的 01 / 06 编号、细分隔线、作品分类、坐标式小标签、图片注释、按钮中的箭头/播放图形、底部信息栏、状态标注。**后台界面应删除无用 PRO/New 徽章、导航 emoji、火焰/火箭、指标后的感叹号等表达性噪声；保留真实的未读数、风险标记和业务状态。**装饰性乱码、条形码、虚构技术参数不算高级。

### R9. 按页面叙事选择非模板布局

内容可以采用不等尺寸 Bento、错列 Masonry、叠卡滚动、左右分屏、无缝横向字幕、分层浮卡等布局语法，但每种都有适用场景与交互边界，见第四节。

### R10. 用实现质量消除“效果图味”

页面要真实可用：移动端重排，链接按钮有效，内容不是占位符堆砌，字体可加载或优雅回退，图片可访问，交互有焦点态，动画尊重 `prefers-reduced-motion`，性能和可访问性不被视觉特效破坏。对于 Dashboard，图表必须有可信数据、时间范围、单位、标签、必要的对照基准与非颜色的可辨识方式。

## 三、四种有辨识度的首屏配方

以下四种配方对应用户截图中实际可见的示例。使用时**借鉴设计原则，不照抄示例品牌、作品或文案**。

### A. 暗色画册／印刷感首页（IMPRINT 式）

**场景**：艺术厂牌、影像工作室、书籍、设计出版社、实验性品牌。

- **构图**：参考 16:10 桌面画幅。深黑或煤灰背景，非均分的杂志网格；左侧巨大字标，中央一幅高挑竖版彩色抽象作品，右侧只有极少量说明。
- **层级**：巨大几何无衬线字标 ＞ 竖版艺术图 ＞ 右侧微型说明与编号；大块空白承担呼吸感。
- **细节**：1px 细线、角标、页码、边缘微型字、编辑式图注；有选择地使用印刷颗粒和低对比纹理。
- **动态**：轻微图像位移/淡入、作品切换，避免满屏粒子或浮夸动画。
- **禁忌**：整齐的三栏功能卡、居中口号＋双 CTA、无意义的 UI 面板、把作品缩成小缩略图。
- **落地检查**：即使移除所有装饰细节，巨字—竖图—说明三者仍形成强而清晰的版面。

### B. 设计师作品主角／黑红画廊（DAODAO 式）

**场景**：视觉设计师、数字艺术家、创意开发者、导演、个人工作室。

- **构图**：近黑色基底，红色高亮；左侧用大标题（如 `I'M ...`）与身份说明建立个人声音；右侧设置大型**圆形**主视觉或影像窗口，叠加可信的播放入口。
- **下沿**：横向且带弧形节奏的作品画廊，作品大小、透视和排列可不同，呈现“真实作品站”而不是产品卡片商城。
- **细节**：简洁顶部导航、人格化微文案、项目分类/年份、红色按钮、克制暗红描边。
- **动态**：画廊横移、hover 预览、播放视频/项目详情；确保每张作品可点、可进入真实内容。
- **禁忌**：千篇一律的“你好我是设计师＋技能图标九宫格”；全部作品挤进相同大小卡片；空洞浮夸的自我介绍。
- **落地检查**：人物身份、代表作品、进入作品的路径三者能一眼被识别。

### C. 概念产品发布／精密硬件叙事（DAYDREAM 式）

**场景**：消费电子、工业设计、概念设备、实验硬件、未来产品。

- **构图**：黑色背景、红橙色地面反射光；左侧或中左区叠放三台不同角度的倾斜产品设备，右侧使用富性格的**像素风标题**，形成硬朗技术气质。
- **导航与信息**：顶部小巧的胶囊导航；标题下方一段简短解释；底部清晰列出三项**真实**关键参数（无参数则换成可验证卖点）。
- **光影**：产品边缘和落地阴影需准确，一处红橙主光源即可；适量材质反射，避免廉价霓虹。
- **交互**：设备视角或款式切换、规格探索、影片播放均应具有真实结果。
- **禁忌**：无产品依据的参数、过多“科幻”噪声、任何没有精度的悬浮设备贴图。
- **落地检查**：产品是主角，标题与参数服务产品，而不是反过来。

### D. 创意工作室／巨字压场的海报首屏（NEXOR 式）

**场景**：高端 agency、品牌设计、数字体验工作室、商业影像机构。

- **构图**：有深度的橘红渐变/舞台光背景；超大工作室字标横贯画面，并**有意识地穿过人物主视觉**，形成明确前后遮挡关系。
- **信息分区**：左下角是简短服务主张和说明，右下角是联系入口或简洁的项目咨询表单；顶部保留很轻的导航。
- **层级**：人物与字标是唯一冲突点，其他内容不抢戏；用暗部稳定可读性、用暖光聚焦人物。
- **动态**：极轻微的镜头推近/分层运动、按钮反馈；不搞无意义大幅滚动动画。
- **禁忌**：常见 SaaS 分屏插图、三列价值卡、模板化客户 logo 墙、无法阅读的文字遮挡。
- **落地检查**：品牌名称即便与人物叠压仍可辨识；联系 CTA 在桌面与移动端都找得到。

## 四、六种现代页面布局语法（Layout Vocabulary）

> 这是“可选择的版式词汇”，不是必须同时使用的组件清单。

| 布局 | 结构要义 | 适合 | 避免的问题 |
| --- | --- | --- | --- |
| **01 Bento Grid / 便当盒网格** | 以**大小不同**、跨行跨列的模块形成视觉节奏；大块主视觉配小块证据/功能 | 作品概览、产品能力、编辑精选 | 等大圆角卡铺满、每块内容权重相同 |
| **02 Masonry / 瀑布流布局** | 列宽可控，卡片高度不同、按列错落；依内容自然生长 | 摄影、插画、案例画廊 | 阅读顺序混乱、图片突然跳动、无法键盘访问 |
| **03 Card Stack / Stacked Cards / 卡片堆叠** | 随滚动逐张覆盖、推出或粘滞展示，形成章节递进 | 故事型案例、产品叙事、服务流程 | 无法跳转、滚动劫持、卡片遮盖文字 |
| **04 Full-page Split Screen / 左右分屏** | 大幅左右分区：左叙事文字，右沉浸媒体（也可镜像） | 工作室首屏、故事介绍、双主题产品 | 机械 50/50、移动端文字与图片断裂 |
| **05 Marquee / Infinite Ticker / 无缝跑马灯** | LOGO、关键词或项目标签水平循环滑动，承担节奏/品牌感 | 品牌合作信息、栏目导航、短标签 | 长句难读、快速滚动、真实内容无法访问 |
| **06 Overlay / Layered Cards / 图层叠放** | 卡片或媒介跨越容器边界，前后层次明确 | 视觉海报、品牌故事、艺术作品展示 | 遮挡关键信息、阴影过重、随意绝对定位 |

**具体使用约束**：

- **Bento**：大卡应有真实内容主次，而不是随机尺寸。移动端按语义次序压成 1–2 列。
- **Masonry**：保持自然图像比例，预留尺寸以避免 CLS；键盘/屏幕阅读器顺序应合理。
- **Stack**：优先 `position: sticky` 等可回退机制；内容在关闭动画/减少动效后仍能正常浏览。
- **Split**：桌面不必严格对半，可按内容需求用 40/60、35/65；移动端自然上下排列。
- **Marquee**：内容不可作为唯一信息来源；支持暂停/减少动效；确保重复项不制造多次可访问性噪声。
- **Overlay**：严格管控 z-index、裁切、断点、对比度；文字被压到图层下方时需重新排版而非减小字号硬塞。

## 五、完整视频案例：从「AI 感紫色后台」到「克制的产品级 Dashboard」

**资料边界：** 用户另附了一段约 8.9 秒、无可辨听语音的屏幕录制。视频展示一个 `EmberAI` 风格的紫色高装饰度后台，被逐步调整为名为 `Ember` 的中性深色分析界面。下述是**实际可见的视觉前后变化 + 从中提炼的工程做法**。视频没有提供原作者的完整设计解释、实际数据源、可用性测试或完整页面，不能把视频中的示意数字、图形或尺寸当作通用事实或标准。想看时序对照，可读 `references/video-timeline.md`，并查看 `assets/dashboard-before.png` 与 `assets/dashboard-after.png`。

### 5.1 视频按时间分解

| 时间位置（约） | 画面中可见的改动 | 应当提炼的原则 |
| --- | --- | --- |
| **0.0–2.4s：原始状态** | 大面积高饱和紫色背景、紫/蓝发光按钮、描边卡片、胶囊徽章、emoji 导航、`Welcome back, Damir!`、粉紫圆角柱形图；左侧还出现间距数字及测量辅助线 | 先识别视觉噪声与错乱的层级，而不先调单个按钮 |
| **2.5–3.2s：降低色彩刺激** | 紫色大氛围逐渐变为黑/炭灰外壳，亮紫卡片和高亮选中态被压低，图表柱形趋于灰色 | 大面积中性色打底，让状态色、数据、内容成为真正的焦点 |
| **3.2–5.4s：规整应用骨架** | 出现对齐参考线；侧栏、搜索框、导航行、分隔线、卡片边界更统一，胶囊彩色徽章陆续收敛 | 用统一栅格、对齐和 spacing tokens 替代靠视觉特效补救的松散排布 |
| **5.4–6.4s：减少装饰与信息噪声** | 品牌由 `EmberAI` 转向更简洁的 `Ember`，彩色表情/多余胶囊标签减弱，导航图标逐渐统一，欢迎语替换为 `October 2026` | 品牌装饰收敛；页面标题交代任务和时间上下文，产品文案减少无用情绪词 |
| **6.4–8.9s：深化数据叙事** | 顶部关键指标仍保留，卡片中的产品插图改为更低调的深色银行卡式构图；主要图表从灰色柱状图转向带刻度、月份、区分色的多条曲线及对比线 | 视觉重心由装饰转为数据。图表要有维度、比较含义和可解释的编码，而不是只做漂亮形状 |

### 5.2 前后差异：操作级改造清单

| 层面 | 之前的「AI 模板味」 | 之后的改善方向 | Agent 执行动作 |
| --- | --- | --- | --- |
| 应用底色 | 大块紫色渐变、背景本身抢镜 | 极深灰主壳 + 稍浅的内容表面 | 把背景、侧栏、卡片、hover、选中态划分为有限的中性层级 |
| 光效 | 卡片蓝紫光晕、高亮描边、玻璃质感处处可见 | 大多数容器使用低对比边线，少用/不用发光 | 删除无业务含义的 `box-shadow` 彩光、`backdrop-filter`、多层渐变 |
| 品牌 | 图标、`PRO`、通知装饰、强烈的高亮都争夺首屏 | 简洁标识与低调的工具操作 | 对徽章逐一做**功能性审查**：有权限/状态意义的保留，否则移除 |
| 页面标题 | 巨大 `Welcome back, ...!` 抢走关键指标注意力 | 更具体的 `October 2026` 时间语境 | 默认先显示当前任务、报告主题或所选时间范围；问候语仅在确有帮助时使用 |
| 导航图标 | 表情符号、风格混杂的彩色小图标 | 单一图标家族、统一线宽和视觉面积 | 统一 Lucide 等已安装图标库，不用 emoji 替代真实图标 |
| 导航选中态 | 蓝紫渐变、发光胶囊，过度像广告按钮 | 中性表面高亮 + 必要的轻微对比 | 仅活动项有明显但克制的背景、字体/图标强调；保留 hover、focus、active 区别 |
| 侧栏信息 | 计划数值穿在五颜六色的小药丸里 | 彩色小点提示类别 + 右对齐的普通数字 | 只有类别需要颜色时才加颜色标记；数值本身保持对齐、可读 |
| 卡片 | 半透明彩色大片、圆角/描边过强 | 深色实面、细边界、稳定的信息内边距 | 设置卡片层级、内边距、标题/数字/趋势的固定排版规律 |
| KPI 表达 | `$48,210` 与 emoji、火焰、`+12%!!!` 并置 | 大数字清楚，增长用小号语义色和比较说明 | 格式化金额、变化方向、百分比；明确 `vs last month` 这类基期 |
| 装饰图像 | 单个浮动小图贴在统计卡上 | 与卡片主题有关的低调局部实体图像 | 确保插图对应真实对象；无价值就删，不要为了填空放素材 |
| 图表 | 同色大圆角柱，仅装饰性展示，坐标与含义弱 | 明确横纵轴、时间维度、可区分系列的图表 | 使用真实数据和合适图形；提供单位、刻度、legend/tooltip/表格替代 |
| 内容密度 | 标签、消息提醒、感叹号、胶囊、渐变同时出现 | 关键业务信息优先，辅助信息留在次级层 | 删除非必要标签，按扫描路径呈现页面名称→ KPI→趋势→明细 |
| 网格间距 | 截屏上有若干测量标注（例如 21/35/41px），但未能证明这些是最终规格 | 改造中明确观察对齐参考线与容器节奏 | 用 4/8 系列间距令牌和明确栅格统一，而非照抄视频中的标注数字 |

**重要限制：** 最终的多曲线画面是一种**视觉参考**，不能据此凭空制作对称的正负曲线、虚构数据系列、误导的趋势或假金额。必须由真实业务数据与业务问题决定是折线、柱状、面积、表格还是单值 KPI。高品质 ≠ 一定使用花哨图表。

### 5.3 后台界面专用的 12 条硬规则（P1–P12）

**P1. 先诊断应用类型，再决定视觉强度。** B 端界面的主角是任务和数据。欢迎语、氛围渐变、品牌故事都不应盖过工作内容；若确有空状态或新手引导，则另行安排。

**P2. 明确应用骨架（App Shell）。** 将 sidebar、topbar、content、filter、KPI、chart、table 分层。侧栏选择项与主内容边界稳定；保持清楚的水平对齐线，避免区块漂浮。

**P3. 减少表面种类。** 大面积选取两到三层可区分的中性色表面，不用每张卡片都换颜色；背景、边界、hover、focus 各司其职。*不强制整个产品改成黑白*，已有品牌可保留符合任务的颜色体系。

**P4. 统一间距与网格。** 选定 spacing scale（如 4/8/12/16/24/32px），统一侧栏内边距、菜单行高、卡片间距、标题/指标的节奏。截图出现的测量数字只是过程观察，不是规范值。

**P5. 建立排版层级。** 页面标题/所选时间窗 > KPI 数字 > 模块标题 > 变化说明 > 次级标签；字重、字号和颜色要相互配合，减少全大写的高密度文字。正文、控件与小字仍需可读。

**P6. 用真实的信息上下文替换套话。** `October 2026`、`Revenue`、`vs September` 是结构例子；实际应按所选报告、时间范围、币种和时区呈现。不要机械把每个首页标题都变成月份。

**P7. 用统一图标代替 emoji。** 选择一个图标库，统一大小（如 16–20px）、stroke、对齐与上下文含义；真实语义的通知数和状态徽章可以保留。

**P8. 对徽章做减法。** `New`、`Hot`、`PRO`、🔥、🚀、`!!!` 不是设计层级。只有当新功能、套餐权限、异常或实时状态对决策有意义时才显示，且必须有数据依据。

**P9. 使用语义色。** 成功、增长、风险、警告、选中、系列色彼此区分；不要把绿色当作“所有数都变好”的默认颜色（成本、逾期、缺陷数量增加常是坏消息）。状态既用颜色也用文本/图标表达。

**P10. KPI 必须完整。** 指标至少明确数值、单位/币种、指标名称和统计区间；显示变化率时注明比较基准；空值、缺失数据、小样本、极端值和负数有合理处理。

**P11. 图表为分析服务。** 根据任务选择图形，给出真实时间轴、数值轴、刻度、系列标签/图例、tooltip、空值处理、数据来源；图表高亮色有意义，不能仅为“视觉更丰富”编曲线或镜像负值。

**P12. 先删噪声，再加细节。** 优先删去多余光效、色条、标签、装饰图、无价值卡片；确保键盘焦点、hover、选中、加载、空状态、错误提示、响应式、数据表格可用后，才考虑微动效。

### 5.5 后台改造顺序：将“去 AI 味”变成可复验操作

1. **截基线**：现有页面桌面 + 窄屏截屏，列出 3–8 个噪声源，标注需保持的功能和业务关键指标。
2. **删视觉噪声**：逐项清理大渐变、霓虹 glow、滥用玻璃卡、渐变按钮、装饰 emoji、无价值徽章、假图表/插图。
3. **整理结构**：固定 sidebar/main 的层级、对齐基线、导航分组、搜索、时间范围与页面标题；统一令牌。
4. **重排内容**：业务任务/报告上下文 → KPI → 趋势/维度 → 表格/操作。不要为了模仿视频而删去有意义的业务模块。
5. **精修数据表达**：金额格式、单位、增减方向、比较基准、日期、系列图例和可解释 tooltip；校验没有伪造数据。
6. **恢复可用性与状态**：侧栏折叠、Tab、过滤器、页面跳转、筛选、分页、表格操作、加载/无数据/错误状态和键盘焦点。
7. **回归审查**：1440/768/390px 下布局、溢出、标题裁切、滚动区域、工具提示遮挡；对比改造前后关键业务流程。
8. **汇报具体差异**：列出删掉的噪声、重新定义的层级、保留的业务信息与未验证项。不得只说“高级了”。

## 六、将视觉语言转成代码

### 推荐的设计令牌（是方向示例，不是所有项目通用模板）

```css
:root {
  --bg-ink: #0e1011;
  --bg-surface: #191c1e;
  --text-main: #f3f0e9;
  --text-muted: #a6a7a3;

  --page-gutter: clamp(20px, 4.2vw, 76px);
  --display-size: clamp(4rem, 10vw, 11rem);
  --body-width: 60ch;

```

这些数值只表达「深色 + 强主次 + 舒适留白」的示意。优先遵循项目已有设计系统；不要把所有页面都做成同一套黑红皮肤。

### 技术与交互底线

- 使用有语义的 HTML（`header`, `nav`, `main`, `section`, `h1`, `button`, `a` 等）。
- 在实际屏幕条件下检查 1440px 桌面、768px 平板、390px 手机，并关注超宽与窄屏；避免横向溢出。
- 使用 `clamp()`、CSS Grid/Flex、合理 `minmax()`，而非只靠固定像素定位。
- 优先用真实图像资产、正确的 `aspect-ratio`、响应式图片；保留清晰度并减少加载抖动。
- 运动是叙事辅助：仅用于作品切换、图层关系、导览反馈；尊重 `prefers-reduced-motion`。
- 按钮、链接、表单要具备真实状态、清晰焦点、键盘可达、适当对比度；背景动图不能遮挡内容。
- 巨字可在桌面部分出框，但移动端不能失去品牌/页面主标题；文字内容不宜全部做成图片。
- 避免过度依赖第三方动效库；能用 CSS 实现的轻量交互先用 CSS。

## 七、审查「AI 味」：发现即改

| 典型症状 | 为什么像模板 | 具体替代方案 |
| --- | --- | --- |
| 居中大标题＋小字＋两个按钮＋渐变背景 | 高频泛用 SaaS 结构 | 主视觉偏置、巨大品牌字标、强画面层级或分屏故事 |
| 3×3 等宽等高圆角卡 | 没有内容主次 | Bento 尺寸分级、Masonry、编辑式章节布局 |
| 全站紫蓝光球、玻璃卡、霓虹描边 | 装饰大于内容 | 中性色背景＋单点品牌色＋真实材质/作品 |
| 图标＋标题＋两行描述重复十几次 | 信息机械均匀 | 精选 3–5 个有证据的卖点，改为图文案例与叙事 |
| 所有内容严格居中、对称、等距 | 缺少视觉方向 | 不对称网格、错位主图、受控叠压、杂志版心 |
| 每一屏都塞入卡片和按钮 | 留白和停顿缺失 | 删掉次要模块，允许纯视觉段落与短注释 |
| 图片彼此风格不一致 | 缺少艺术指导 | 统一色温、光照、构图、摄影与产品渲染语言 |
| 很多看似专业的虚假数字/标注 | 伪细节破坏可信度 | 使用真实可验证资料；无资料时删除不编造 |
| 只适配桌面效果图 | 不是可上线设计 | 手机重排、溢出测试、键盘/动效/加载状态测试 |
| 为了“高级”字极小、对比度极低 | 牺牲使用体验 | 微型标注可小，正文/操作控件必须清楚易读 |
| Dashboard 大面积紫色渐变、发光胶囊、发光卡 | “炫酷 SaaS 后台”的高频套壳 | 低刺激中性色表面，关键状态语义色，小范围高亮 |
| 导航里 emoji、彩色图标混搭、每行都有徽章 | 噪声压过导航路径 | 统一图标家族和导航选中态，删除无业务意义的徽章 |
| 欢迎语夸张，数据指标无时间范围和基期 | 视觉表演大于业务解释 | 任务或时间上下文标题、真实 KPI/单位/比较基准 |
| 图表只有漂亮渐变、没有轴标签和单位 | 无法判断数据是否可信 | 正确轴、图例、单位、tooltip、空值与真实数据语义 |

### 五个最终判断题

1. **辨识度**：移除 LOGO 后，这个页面是否仍有区别于常见 SaaS 模板的构图语言？
2. **注意力**：首屏是否能指出唯一视觉焦点，且第一眼知道品牌或产品是什么？
3. **真实性**：图片、数据、作品、微文案与交互是否都有真实含义？
4. **一致性**：字体、网格、留白、色彩与运动是否服务同一个方向？
5. **可用性**：窄屏、键盘、低性能设备与减少动效时是否仍完整可用？（后台还需核验数据和操作）

任一项不成立，先修正它，再添加装饰。

## 八、实际执行流程（代理必须遵守）

### 新建页面

1. 明确品牌/用户/目标；缺少信息时采取合乎任务的默认方案，必要假设写清楚。
2. 列出页面内容优先级，挑选 **A/B/C/D 一种首屏配方**，可按实际题材改造；不得机械照抄截图。
3. 选择 **一种主布局 + 至多一种辅助布局**，解释为何贴合内容。
4. 先确保真实内容与主视觉，再落实设计令牌、字阶、版心、对齐、负空间及细节。
5. 编写可运行代码，优先适配用户项目已有组件/路由/设计系统。
6. 如可使用浏览器/截图工具，分别审查桌面和移动端，修复遮挡、裁切、对比度和死链接。对于功能后台，额外审查数值准确性、数据图表语义和业务流程。
7. 用下述交付格式描述设计逻辑与验证情况。

### 改造已有网页

1. 保留用户明确要求的业务功能、交互语义、品牌约束和重要内容。
2. 先指出视觉模板化最明显的 3–5 个问题，再确定一套新构图方案。
3. 优先调整**整体构图、视觉主次、字阶、素材、留白**；不要只改按钮圆角和背景渐变。
4. 只在有理由时加入滚动叠卡、浮动层、跑马灯或复杂动效。
5. 对视觉改变进行回归测试，确认业务流程没有被破坏。

### Dashboard / 管理台去 AI 味改造

1. 默认保留既有应用架构、路由、权限、数据流、表单、图表所用数据及交互；设计不是重写业务。
2. 按 **P1–P12** 审计紫色渐变/霓虹、emoji、无用徽章、虚假数字、含混图表、间距偏差。
3. 先定义 neutral surfaces + semantic colors + type scale + spacing，再调整 App Shell、侧栏、搜索、KPI、图表。
4. 使图表反映真实数据与分析目的；视频中的多曲线造型只是可见案例，不能复制为伪数据。
5. 进行页面与功能回归，不可只提交“静态设计稿”。

### 用户只要生成提示词时

输出简短但具体的可复制提示词，至少包括：**页面类型＋主视觉构图＋左右/上下信息分区＋字体层级＋色彩/光影＋细节＋布局行为＋明确不要什么**。禁止只说“高级、科技、极简、有设计感”。

## 九、交付格式

交付结果时用简短文字说明：

- **艺术方向**：本次选择的视觉概念以及为何符合内容。
- **关键结构**：首屏焦点、信息层级、所用的主/辅布局。
- **去模板处理**：具体删掉了哪些泛用模式，加入了哪些有意义的独特细节。
- **适配与验证**：桌面/手机/可访问性/动效做了哪些检查；如果是 Dashboard，说明指标基期、数据来源、图表含义与交互回归的核验情况。未检查的如实说明。

不要只声称「已去除 AI 味」。必须在设计与代码中可观察到变化。

## 十、五段可直接复用的生成提示词

下面给出的是方向性配方，可替换品牌与内容；不是让所有项目使用截图中的名字。

**印刷画册：**
> 生成一页 16:10 优先、可响应式扩展的暗色艺术品牌官网首页。深黑背景，杂志印刷网格，左侧巨大品牌字标，中央一幅竖版彩色原创艺术作品，右侧仅保留极简品牌说明；精密细线、编号、微型图注、大片留白。文字排版大胆但准确，图像是主角。不要等宽模板卡、蓝紫渐变、通用 SaaS Hero。

**设计师作品集：**
> 生成黑底、鲜红高亮的设计师个人作品集。左侧超大个人宣言、身份介绍与一个清晰作品入口，右侧圆形影片/作品主视觉及真实播放行为，底部横向弧形节奏的作品画廊；强化作品叙事与微交互。像独立设计师真实上线的站点，避免技能九宫格、千篇一律作品卡。

**概念产品：**
> 生成一页精密概念硬件发布首页。近黑背景、局部红橙地面光，三台倾斜设备以可信透视叠放作为焦点；一侧用锐利像素风展示产品标题与简洁说明，顶部胶囊导航，底部三项真实产品规格。材质反射与阴影精致，运动克制。不要廉价霓虹、虚构参数或科幻噪声。

**创意工作室：**
> 生成高端数字创意工作室首屏。橙红舞台渐变与深色区域形成强光影对比，巨大品牌字标与高质量人物主图产生有意识的前后穿插；左下角放服务宣言与简述，右下角放清晰联系 CTA/小表单，顶部轻量导航。排版有网格却不死板，像品牌 agency 的定制海报官网；不要普通 SaaS 分栏与功能卡。

**后台 Dashboard：**
> 对当前管理后台进行一次以真实业务信息为中心的去 AI 模板感改造。保留现有路由、权限、数据和交互。审计并移除大面积紫蓝渐变、卡片发光、玻璃拟态、emoji 导航、无用 PRO/New 徽章、没有业务价值的欢迎语和花哨图形；使用中性深浅表面、克制边界、统一侧栏图标与选中态、规律的 4/8 系间距。让页面标题明确报告与时间范围，KPI 清楚说明单位和比较基准；图表从真实数据出发，标出轴、单位、图例与 tooltip，不生成虚假趋势。保证各交互状态、窄屏和键盘可用。像经过资深产品设计师与前端工程师联合打磨的系统，而不是漂亮的静态 mockup。
