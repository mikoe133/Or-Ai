## 入口与版本

`/admin/content/:productId?tab=project` 是项目入口，无参数的商品内容页默认进入该视图。原带 version/profile 的链接仍保留原编辑入口。

| 选择 | 对应内容 |
| --- | --- |
| plan | 明确计划修订；省略时读取最新计划。仅关联同一计划的当前制作记录与固定方法 |
| run | 固定外部批次；只使用该批次已接受的输出与最新尝试，不混入其他批次的 latest |
| review | 固定审核 manifest；计划、方法、产物、原件与正文均按该修订回读 |
| node | 目录、画布与详情互相定位；方法/产物自动展开所属模块，聚焦会跟随定位 |

计划、批次、审核选择分别分页。不同商品、不同 scope、计划与所选批次/审核不匹配，服务器直接拒绝。无法读取的引用显示明确错误，不回退成其他版本。审核快照与 run 分别查看。

## 正式能力

- 项目目录、关系画布、单模块依据展开、最多 5 个模块聚焦、完整总览、检索与手机等价列表。40 模块以分层分组布局展示；最新计划可添加模块、编辑模块依赖、保存新计划修订，拖动/整理布局可独立持久化。既有固定方法快照、来源及归属关系只读，历史计划只读；O2 的新商品方法以追加快照保存。
- 方法正文、固定基础版本、商品参数/补充方法与完整展开正文；完整方法 JSON 快照和固定附件分别取回，不依赖基础库当前草稿。
- 题目/报告方案/文案原文及结构化原件导出、真实图片/视频预览与下载、原生体验演示报告和体验清单导出。网页/3D 原件按附件取回，不将清单或预览显示为实际原包。
- 原件导入中、失败、到期、已导入但未关联等状态分开显示；外部地址是来源链接，实际下载始终使用平台固定原件。
- 外部运行回执、原 jobId、失败原因与需复查；固定方法和产物支持双向定位。无实际产物就不绘制成功产物节点。
- 实际原件/固定引用检查、审核部分稿、提交、指定模块与原因退回、修改后保存新候选并重交、审核留存。变更使旧提交失效；重复请求沿用幂等意图，失败不显示未保存成功。
- 已留存的历史关系独立回读。审核留存不改变商品上架状态或全局 skill 状态。

手机详情使用原生模态窗口，支持 Escape、焦点恢复与长正文滚动；桌面目录与详情各自滚动，页面滚动保留在运营区域。React Flow 保留免费版 attribution，正式依赖 `@xyflow/react 12.12.0`（MIT）。

## 后端与边界

`GET /api/admin/products/:id/project-workspace` 在 repeatable-read 事务中聚合明确版本，复用既有计划/方法/制作/审核/回执模型。仅接受真实管理员 Cookie 会话，保留 Origin、CSRF、no-store 和固定 scope；机器凭据不能调用该聚合接口。它不返回消费者答卷或个人报告。

原件下载、审核预览与状态操作分别调用已有 P4/W 权威接口。GET 视图不宣称重新扫描所有文件字节；“重新校验”及提交/留存会做实际校验。内容与语义质量仍需人工审核，平台不会凭客户端 finished 或脚本替代实际交付物。
