# 平台宗旨与商品整体创作设定

日期：2026-10-19。状态：T12-A 已实现创作设定修订与报告方案草稿契约/API，完整编辑工作台、采用链及新呈现模板仍待后续任务。平台提供情绪价值，帮助用户加深对自己、对方以及关系的理解。题目、互动、报告、视频、文案和封面按同一商品设定配套制作。

本文件定义各制作领域共用的依据；[CONTENT-BACKOFFICE.md](CONTENT-BACKOFFICE.md) 负责分领域内容、skill/MCP 与引用，[EXPERIENCE-PLATFORM.md](EXPERIENCE-PLATFORM.md) 负责运行形式与评估机制。沿用 T12–T17 补充子任务，不新增一套并行实施计划。

## 1. 商品先确定用户价值

每款商品在制作前写清两个目标：

- 情绪目标：用户希望获得何种感受，例如被理解、被接纳、轻松、有趣、好奇、获得表达的勇气或感到连接。
- 理解目标：用户希望看见什么，例如自己的需要/偏好、某类场景中的行为、与他人的差异、关系中的期待，或下一次可以尝试的沟通方式。

内容需要给出可理解的观察、解释或行动，允许温柔、幽默、奇幻、冒险等不同风格。报告围绕真实输入与既定规则组织表达，类型和分数作为解释工具，不以人格高低或关系输赢作为商品价值。

平台品牌层面采用尊重、好奇、鼓励探索的表达；每款商品可选择自己的情绪节奏和视觉世界。题材、3D 技术或完成率本身不代表商品已实现情绪价值，需通过成套内容与实际试读/体验判断。

## 2. 每款商品有一份版本化创作设定

在已有共享选题说明上完善 ProductCreativeProfile（逻辑名称待实现时固定），由 Product 关联明确修订。所有领域读取同一设定并做媒介适配；各自的 skill 库和专业输入/输出仍独立。

此前规划中的 briefRevisionId 在实现时映射到此设定修订或保留兼容别名，不维护两份不同的共同创作依据。旧商品使用明确的兼容方案，新增设定不反向改写旧报告或宣传成品。

| 设定部分 | 必需说明 | 影响的制作环节 |
| --- | --- | --- |
| 人群与使用情境 | 面向谁、何时体验、想讨论什么 | 题目、体验入口、文案与报告 |
| 情绪与理解目标 | 体验后希望有什么感受和发现，能带走什么 | 全部产物 |
| 参与视角 | 自我探索、单人关系视角；未来另支持双方分别参与 | 题干、结果范围、报告称呼和宣传承诺 |
| 形式与体验节奏 | 网页/卡牌/2.5D/3D/小游戏，节奏、时长、确认/反馈与结束方式 | 交互与报告承接、宣传视频示例 |
| 世界观与核心意象 | 例如小屋、花园、航行、冒险；角色、物件与象征的含义 | 场景、题目措辞、报告、封面和视频 |
| 视觉/声音 | 参考素材、配色、字体/排版、图形/角色、画幅适配、动效/声音节奏 | 体验、报告、封面、视频及分享卡 |
| 语言表达 | 叙述视角、语气、常用意象、结果命名和行动引导方式 | 题目、报告、口播/字幕与引流文案 |
| 报告方案 | 希望提供的洞察与建议、章节、叙事形式、展示模板/主题、分享摘要 | 报告写作和呈现；公开样例/宣传须对应 |
| 制作任务清单 | 各领域交付物、兼容的 skill 版本、必要输入和采用标准 | 后台编排、MCP 上下文和整套验收 |

风格一致指主题意象、表达和实际承诺相互支持；平台画幅、视频节奏、文字长度可以适配。3D 商品的报告可采用同世界观的二维地图/图文，也可选择兼容交互模板，以可读、可恢复和内容准确为准。

## 3. 报告是独立设计的最终交付物

报告同时需要内容设计和呈现设计：

1. 报告内容回答这次选择体现了哪些倾向/需求、在哪些场景可能出现、可以如何理解，以及能尝试什么。关系题材区分自己的期待、感受和可观察的互动。
2. 报告表达随商品设定，例如一封回信、房间地图、探索日志、角色卡或共同讨论手册，使用同一套意象和语言。
3. 报告呈现使用兼容模板，定义章节、图表、插画、排版、动效及分享卡；结构化结果与表现层分别管理。

现有 assessment 领域在 skill 用途上明确“题目/规则设计”和“报告写作”两个专业角色；experience 领域负责报告呈现模板/主题。两者可以采用各自的 skill，但必须接收同一创作设定和锁定的评估/内容版本。宣传视频、文案和封面引用经过选择的报告样例、场景及素材。

当前后端报告字段是类型、维度、解释和建议等固定结构，尚无任意章节或主题化报告运行器。T12 定义可版本化的结构化报告方案/内容模板，T15 定义报告呈现模板及兼容投影；新增结构需校验和适配，保留旧报告快照。创作设定或风格不能修改已经生成的分数、结果事实及私人归属，也不意味着接入实时 AI 解读。

## 4. 成套商品示例

以下仅为创作示例，非已实现商品或承诺的测量效果。

| 商品方向 | 情绪/理解目标 | 体验与报告 | 传播配套 |
| --- | --- | --- | --- |
| 社交电量小屋 | 被理解，发现舒服的社交节奏和恢复方式 | 温暖手绘 2.5D；报告为房间/能量地图、恢复建议和一段回信 | 同画风小屋封面，展示真实选座片段的视频，邀请探索自己的节奏 |
| 我的关系花园 | 表达期待，理解自己在关系中需要什么 | 花园意象、场景选择；报告为我的观察/需要、差异线索和沟通邀请卡 | 同角色/植物与配色，展示互动及可公开的报告节选，文案以邀请对话为主 |
| 边界冒险日志 | 轻松、有力量，练习表达需要 | 像素冒险或小游戏；报告为选择回顾、表达卡和下一次尝试 | 像素角色封面、实际关卡片段、冒险语气的文案；新评估玩法由 T17 单独验证 |

制作时先固定价值目标与创作设定，再选择各领域的兼容 skill。每件产物返回其实际引用、创作设定修订和使用快照，素材包固定整套采用清单。

## 5. 单人和双方关系探索分别定义

现有平台是一份权益/答卷对应一位作答者的记录。单人关系商品可以提供其视角的理解、反思和邀请对方讨论的问题，也能用于双方一起看内容；报告不能把这些数据写成双方已经共同回答的结论。

双方分别作答、匹配、对照和共同报告是后续独立能力，需要先确定邀请/参与、各自同意分享的范围、共同结果与私人答案的界限，以及退出/撤回后的展示。该方向与平台宗旨一致，但尚未加入当前单人引擎或原 v1 必需验收；不因出现“共同探索”文案就宣称已有双方报告功能。

## 6. 制作与 MCP 契约

每次制作上下文至少绑定 productId、creativeProfileRevisionId、内容/评估版本、商品形式、当前领域/用途、相应 skill 版本、所选输入引用和报告方案。context_bundle_get 按权限和当前任务提供这些字段及必要参考；无需把消费者答案交给制作客户端。

领域工具仍负责各自的结构与文件校验。回传产物需声明采用的设定修订、模板/风格变体与来源；服务端检查领域兼容、引用和必需交付项。切换商品主题/形式或报告方案会提示相关上下游复查，旧成品和私人快照保持原样。

后台应提供成套预览：题目/过程 → 报告 → 封面/视频/文案/分享卡，经营者可以核对从传播承诺到实际交付是否连续。自动检查版本/引用/必要字段，人工判断语气、意象、情绪目标和结果表达是否合适，不以相同风格标签直接判定一致。

## 7. 任务落点与验收

- T12：创作设定、情绪/理解目标、参与视角、报告内容方案、成套采用清单和预览。
- T13：各领域 skill 与创作设定的适配，题目设计/报告写作/报告呈现的职责及明确版本绑定。
- T14：所有制作 MCP 使用同一设定修订与任务上下文，上传校验及一致性复查。
- T15/T16：报告呈现与商品形式相配、体验与报告的衔接、旧版/简化呈现兼容及实际设备可读性。
- T17：新玩法的结果可解释并服务于情绪/理解目标，新规则逐玩法验收。
- T11：正式商品试读/体验记录用户是否感到被理解、获得具体发现及可用的表达/行动建议；与转化、完成和退款指标分别记录。

所有新增要求按后续任务验收，当前 T01–T06 本地证据不因此扩展为已支持新报告形式或双方作答。正式商品必须提供一套能核对的实际产物，使用未实现的 3D/游戏形式时相应能力保持待验收。
