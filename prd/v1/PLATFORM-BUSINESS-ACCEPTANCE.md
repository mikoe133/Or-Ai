### O1 能力与约束

**能力：**正式后台提供“连接我的 Codex”统一入口。三项业务操作默认不授权，由运营者明确选择创建商品项目、使用允许的 Skill、上传草稿；可使用自己名下已有工作区，或按分类/项目数/每项目方法数/运行批次数/到期时间新建有限工作区。服务端先返回固定权限摘要，确认后一次保存整组独立领域授权；可查看、交接和整组撤销，不把授权保存称作客户端已连接。`?view=legacy` 保留旧单领域管理入口。

**固定约束：**工作区属于当前管理员和 scope；只能创建/读取/撤销，没有任意修改旧额度或转移所有者接口。数量为 1–100，分类必选，期限 1 分钟至 90 天；连接不能晚于工作区到期，失效工作区不能签发。assessment 才可 projects:create/write；其他领域只取允许的项目、方法和最小上下文。上传依赖明确允许相应领域读取方法；共享 Skill 采用显式白名单，不授予共享库修改、审核、上架或消费者数据访问。新建项目/方法由服务端纳入归属，客户端不能自行扩张范围。原始密钥只在首次响应及当前页面内存中存在，不进入 URL、DOM、Storage、查询缓存或日志；复制时才填入一次性连接说明，离开/隐藏页面即清除，丢失后无法重新读取。

**实现契约：**复用工作区和凭据业务服务，新增 Cookie 管理端 `/api/admin/codex-connections` 的分页/详情、只读 preview、明确确认 create 和整组 revoke；写入沿用 Origin/CSRF、requestId，并以 expectedDigest 固定预览依据、clientKey 固定连接业务身份。一个事务保存新工作区（如需）、连接元数据和各域凭据；失败全部回滚。响应不明时用原请求确认结果，不重复签发，也不重新返回原密钥。列表解释工作区撤销/到期、所有者失效及单领域失效，整组撤销不影响同工作区其他连接。

**设计变更记录：**最初逐领域授权方案假设“无需新表或迁移”，该假设保留为历史范围。用户批准的 R2 改为统一连接入口，为持久分组、原子签发、稳定重试与整组撤销新增 `CodexConnection` 元数据表、凭据关联及第 24/25 份向前迁移；不保存原始密钥，不改旧迁移或历史授权。第 25 份仅排除旧单领域凭据的无关延迟约束事件，保留新连接完整性校验。

**非目标：**不安装客户端、不签发持久真实凭据、不运行模型/媒体、不发布、不创建日程；不把静态设计原型当成 API/Auth 验收。协议测试中的临时凭据仅可在自动回收的隔离 TEST 库里使用。

**验证范围调整：**原计划中的真实本机 Auth 新连接验证，按本轮明确授权收窄为“隔离样例和测试替身”。正式组件使用真实隔离 API/数据库；身份由 Nest 测试提供者替换，剪贴板由浏览器替身拦截。不使用真实登录账号，不签发能访问真实账户的持续授权；既有 Auth 历史证据不扩大成本次连接验收。手机仅为模拟视口。

**开放项：**R2 指定设计及正式实现授权已独立记录；用户后续明确批准三张指定正式 UI，O1 本地关卡闭合。真实账户连接、密钥签发/持续访问、真实客户端配置和真机均未验收。O2 本地技术/指定正式 UI 通过；O3 正式实现/隔离验证通过、正式 UI 待验收，O4 未启动，不根据契约/fixture 勾完成。

**交接：**O1 后续批准见 [user-approval.json](../../output/design-review/codex-connections-o1-formal-20261022/user-approval.json)，三图摘要与最终交付记录一致。原 R1/R2 原型、O1 交付时 pending 状态及各批技术证据保持；R2 设计批准与正式 UI 批准分开记录。O1 的 448 项/11 个新页面情境/57 项旧回归保持为历史证据；后续 O2 设计批准及新的正式验收见下文。

#### 固定规则与交接边界

- 只在当前已保存计划上新固定；历史计划/审核/运行快照只读，规划未保存时先处理规划。模块、基础版本及方法均保持精确修订/摘要，不静默采用共享库最新版本。
- assessment 的题目设计与报告写作分别满足用途；experience 的场景/报告呈现同样分别选择，原五用途 ACTIVE 组合保持现有规则。设计样例先演示四类交付，正式实现保留 experience 可选域。
- 修改商品定制追加另一份快照，旧方法、附件、产物来源和审核依据不变。相同输入/同请求恢复原记录，冲突保留本地草稿；结果未知锁定修改，先用原请求核对，不无故再保存一份。
- 未保存保护覆盖切模块、用途、计划和关闭流程；普通账户、跨 scope、他人的连接/工作区、撤权、过期、错领域、源修订变更和附件损坏必须在正式隔离验证中实际拒绝，不能只靠隐藏按钮。同 scope 管理员已有的共享库管理规则保持，不把所有共享方法改成单一操作者私有。
- 商品参数和补充说明不是共享 Skill 修改，也不是可执行命令授权。库正文/附件仍作为创作数据使用；固定方法和交接说明均不包含身份凭据、服务端存储键或个人答卷/报告。
- 交接基于显式选择的 snapshotId/digest、productId/planRevisionId/planModuleId、共同设定、最小输入与预期输出槽位；不把普通复制当成功运行。正式导出前用服务端当前状态核验，之后实际工具调用仍需重查授权。

### 固定业务规则

- 状态分别展示：最后制作端申报、当前平台接续条件、已保存成果/审核状态、复查信号。尚未开始、缺输入、有效认领、认领到期、批次/阶段到期、次数/并发/申报预算受限与授权失效须明确区分；未知不按 0 元或成功处理。
- 首期停止范围是一份精确 run，不提供未经现有契约支持的“只停一个模块”。需说明原因、核对影响、明确同意，记录当前管理员 actor；停止后不复活此 run，不扩额度/期限，不取消第三方作业。晚回包按现有 W 服务规则拒绝，旧 standalone 草稿/上传兼容边界不扩大成全部写入口被停止。
- 管理端读遵循原 scope/商品权限；停止写入另外核查当前管理员为 run 工作区 owner、归属/有效身份与可操作依据，其他管理员工作区只读。复用当前管理员/Origin/CSRF 与审计，不读取/冒用机器 Bearer，不开放万能身份入口。
- 已保存记录、方法、文件、审核依据与事件历史原样保留。成功模块不默认重做，需复查时可看旧版本，但不能冒充当前可采用结果。
- 恢复以当前尝试为依据；历史尝试只读。有效认领归原客户端处理；其他客户端不抢占。原作业未知或输入变化时先整理原作业查询依据；已报告终态且输入/权限/限制允许时，才整理携带原尝试标识的显式接续说明。
- 接续说明只固定 run/plan/module/profile、attempt/revision/generation、精确方法/依赖记录/必要最小片段、原 provider/jobId、现有允许的连接与下一步；不带真实凭据、leaseToken、服务器存储键/内部下载路径或消费者数据。外部实际调用继续重查权限和 nextAction。
- 原批次/阶段过期、次数或已知申报预算达限、已停止或连接不合规时，不输出可执行的继续制作步骤；给出保全/人工处理依据。本批不创建新 run，不扩限，不推进 O4 的配置/日程；正常有效认领的并发限制应解释为等待，不能冒称永久失败。
- 恢复选择只留当前页，刷新重新核对；不是已保存的恢复任务。导出前服务端重新验证固定摘要、当前回执/代次、连接与文件；有变化则保留用户选择但失效旧预览，重新确认。二进制原件仍按授权另取。

### O4 实施契约（待新设计批准，尚未实现）

**入口与状态：**拟放在“Codex连接”下的“运行配置草稿”，也允许项目工作区带上下文进入，但连接、时间与方法不隐式选定。列表/详情、六步编辑（范围与客户端/时间与产量/来源与输入/方法与分工/工具与限制/核对与导出）、只读历史及未知保存恢复共用后台运营滚动区域。离开/浏览器返回保护未保存内容，手机同等操作和焦点恢复。

**持久化决定：**正式实现预计新增 `ExternalRunConfiguration` 稳定容器和 `ExternalRunConfigurationRevision` 不可变修订两模型及一份向前迁移；此为待审方案，本轮仍71模型/25迁移。容器保存owner/scope/稳定clientKey/currentRevision，修订保存完整nullable草稿JSON、确定性digest、作者和时间。每次保存追加修订，expectedRevision与配置写锁防并发覆盖，requestId/clientKey使失败或丢响应恢复原保存，不重复追加。禁止覆盖旧修订，不存验证结果作为长期授权、不更新现有run/凭据/旧表字段；正式迁移前后重做旧行/迁移SQL/历史引用保全。

**拟新增接口：**管理员Cookie `/api/admin/external-run-configurations` GET分页/POST创建，`/:id` GET详情，`/:id/revisions` GET分页/POST追加，`/:id/validate` POST只读核对，`/:id/export` POST再次核对导出。严格schema、owner/scope、Origin/CSRF、private/no-store；不接收机器身份，不提供执行/启用接口。create/revise使用requestId、clientKey或expectedRevision；validate/export绑定revisionId、digest与观察到的来源/权限frontier，变化返回409并保留选择。未确定的具体schema在实现关卡再编写，不声称现在可调用。

**核对与导出：**平台字段校验与外部环境验证分列。缺项只可导出 `incomplete_review` 待补项清单，不包含制作步骤；字段完整后只可导出 `review_only` 无凭据配置及单任务/按领域多任务分工说明，仍 `enabled=false` / `externalReadiness=not_verified`。两类导出都需明确确认范围且服务端复核当前引用/权限，历史修订只读。清单含固定修订/摘要、约束、依赖绑定/等待条件、缺项/未验事项及手动交接说明；JSON与Markdown不得带消费者数据、密钥、内部存储键/下载路径，二进制另行按授权取回。外部真正执行时仍需重新核对授权与输入，不因清单齐备自动放行。

**单任务/多任务：**单任务按DAG顺序交接；多任务显式分为统筹、题目/报告、文案、封面、视频及可选体验角色，各角色只取本领域方法和最小输入，统筹负责共享run和前置回执。依赖未齐等待，不各自创建重复run；一个模块失败只影响实际依赖，保留成功稿。方案选择只描述未来外部安排，当前不创建任务/代理或锁定模型档位。
