# 商品统一实现规范：Three.js

2026-10-26，用户已确认商品规划变更：所有商品使用 Three.js 制作，所有商品 Skill 明确这一点；动画和交互按具体商品规划决定。本规范覆盖此前将普通网页、DOM 小屋与 Three.js 作为同等新商品技术选项的规划。既有实现与验收记录保持历史事实。

## 已固定的产品规则

1. **每款商品的正常体验必须使用 Three.js。** 场景须实际可运行、与该商品内容相关；普通网页表单、视频背景、空白或装饰性 Canvas 不能代替核心商品体验。
2. **技术基线、视觉风格与玩法分别确定。** 2D、2.5D、低多边形、像素、写实等均可由 Three.js 呈现；选择 Three.js 不等于每款商品必须有自由漫游、复杂模型或小游戏，也不等于统一套静心花园。
3. **动画、镜头和交互由每款商品的固定规划确定。** 可以明确选择静态构图、少量反馈或复杂场景，但不能把未定项目擅自补为固定动画、镜头或操作。减少动态/键盘/触摸和必要反馈仍需按实际商品验证。
4. **全部商品 Skill 都必须明确上述规则。** 题目与评估、报告写作、封面、视频、文案、场景设计、报告呈现共七种专业用途，读取同一创作设定与商品规划，保留各自职责和输出格式。
5. 报告、封面、视频和文案与商品的场景、意象、风格及真实能力对应。各产物按媒介制作；需要交互式 Three.js 报告时在该商品规划中明确，不把 PNG/视频/文案也当作运行代码上传。
6. DOM 可承担文字、无障碍和设备故障回退；正常商品交付仍须有实际 Three.js 场景。旧 DOM/小屋模板仅保留历史、平台测试及兼容用途，新正式商品不能凭这些模板认定已符合本规范。
7. 渲染技术不改变答案、服务端评估、权益、消费或报告归属。排序、分配、分支等新玩法仍按 T17 注册答案与评估协议；动画、相机角度和操作路径不能擅自成为评分依据。

商城目录、登录、账户、运营后台仍使用现有应用页面；本规范针对商品体验及其制作链。它不要求将全部站点 UI 重写为 Three.js。

## 商品制作前必须固定的规划

下表已在2026-10-27的 T16.C2-A 接入严格 v2 制作计划，API/MCP/后台共用，字段归属见[商品规划合同](PRODUCTION-PLANS.md#2026-10-27t16c2-a-商品规划合同)。旧 v1 保持兼容，不自动补成已确定；新正式发布完整性已由任务03接通，验证见[03证据](../../output/implementation/threejs-publication-gates-20261027/verification.md)。不得将文字规划或下拉选项当作相应场景已实现。

| 项目 | 必须说明的内容 |
| --- | --- |
| 用户价值 | 人群、情境、情绪目标、理解目标与可带走的行动 |
| 实现基线 | Three.js，具体 renderer/版本、场景和资源清单 |
| 视觉与空间 | 2D/2.5D/3D 视觉、世界观、构图、配色和画幅适配 |
| 动画与镜头 | 是否需要、何时触发、持续/退出、可否跳过与减少动态策略；未定写待规划 |
| 交互与确认 | 可操作对象/任务、输入方式、反馈、确认、保存和恢复；未定写待规划 |
| 内容与评估 | 内容/答案 schema、完成条件、服务端评估；与实际注册能力一致 |
| 结果与宣传 | 报告形式/意象、封面取景、视频展示片段与文案承诺的固定来源 |
| 验收 | 设备、资源/加载/渲染预算、失败回退和成套业务流程 |

“无额外动画”可以是商品规划中的明确决定；“动画待定”不能被记录成动画已交付。不能仅靠体验形式字段 `3d` 推断具体动画、玩法或完整制作计划。

## 各领域 Skill 的统一要求

共享条款的代码来源为 `packages/contracts/src/product-policy.ts`，七份可导入的起始清单位于 [示例目录](../../examples/threejs-products/README.md)。所有模板都将 `creative-profile` 与 `product-plan` 声明为必填输入，支持形式默认 `3d`，正文显式写明 Three.js 必须使用、动画/交互由商品规划确定。

| 用途 | 在共同规则之外负责什么 |
| --- | --- |
| assessment_design | 题意、明确答案与场景任务的语义映射，不从相机/动画擅自计分 |
| report_writing | 基于真实输入解释结果，承接世界观并给出具体行动线索 |
| cover_design | 商品场景/物件与配色的媒体适配，区分实景与概念示意 |
| video_production | 展示真实具备的场景、动画和交互，区分分镜方案与成片 |
| copywriting | 按实际体验与交付表达价值，未定玩法不写成卖点 |
| scene_design | 实际 Three.js 场景、资源和操作，按该商品规划设计镜头/动画 |
| report_presentation | 结果交付的形式、意象和交互承接，符合结构化结果与注册能力 |

共同条款不能代替各专业 Skill 的完整方法，也不能用相同风格标签代替输入/版本引用。MCP 的 skill/context 工具描述同步这条制作规则；工具描述是制作指引，不替代服务端兼容/发布检查。
