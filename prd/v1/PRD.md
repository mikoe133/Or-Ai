# Or-Ai 主平台 v1 PRD

日期：2026-10-16。状态：实施需求；用户已完成手机/网页 Figma 设计，页面覆盖接入前核对；商品内容为测试占位，本地开发优先、云端接入后置。新增经营者内容后台、风格 skill 与 MCP 的后续扩展规划，未开始实现。

## 1. 本版目标与边界

平台主旨是提供情绪价值，加深用户对自己、对方与关系的理解。消费者通过不同风格/形式的题目与互动获得反思、表达和沟通线索，报告与传播素材共同服务于该商品的情绪/理解目标；制作约定见 [PRODUCT-CREATIVE-SYSTEM.md](PRODUCT-CREATIVE-SYSTEM.md)。

v1 让消费者浏览多个商品，以兑换码领取、保存答题、查看报告和群体反馈；可选邮箱账户归集权益并跨设备访问。经营者维护配置、素材、订单和售后。先用占位商品走通平台，再替换为符合上述目标的正式商品；新形式不自动成为现有代码能力。

固定决策：React＋TypeScript＋Vite、NestJS＋TypeScript、Prisma＋Supabase PostgreSQL、Supabase Auth＋Resend、Cloudflare Static Assets＋Worker＋Containers；Tailwind CSS 固定 3.4。架构与成本细节见 [PRODUCT.md 第 7 节](../../PRODUCT.md#7-技术架构与云服务适配2026-10-09-核验)。UI 不改变这些技术选择。

实施按 [LOCAL-FIRST.md](LOCAL-FIRST.md) 分本地与云端验收：T06-L 通过后可做 T07/T08，真实收信、云端身份与公网验证统一留在 T06-C/T09；T10 的双端响应式视觉可先在本地完成。业务功能和权限验证仍保留，不开放生产认证绕过入口。

T01–T05、T06-L、T07、T08 本地已验收。2026-10-16 的后续顺序以 [ROADMAP.md](ROADMAP.md) 为唯一入口：先补 T06-O 实际操作准备并建设内容/skill/MCP，再推进体验试点、正式视觉与统一云端验收；Three.js/新玩法后置。排期优先级不改变 FR 与 M5/M6 的原硬依赖，本次未启动这些功能。

本版不实现创作者积分/充值、任意代码/skill 执行、AI 商品生成、每日热点自动化、自动向社交平台发布、实时 AI 解读、微信/短信登录、站内支付、平台自动订单同步、组合包或双人测试。长期商业目标保留，后续独立排期。收藏、热门榜、复杂拖拽编辑器也不作为 v1 验收要求。

2026-10-16 新增后台扩展：题库报告、宣传封面、视频、引流文案各有产物库、skill 库及独立 MCP 工具/权限，共用选题说明和稳定商品 ID；通过固定版本的题目/文案块/封面引用组织视频等组合内容。统一约定见 [CONTENT-BACKOFFICE.md](CONTENT-BACKOFFICE.md)，拆为 T12–T14。首期默认由外部 AI 制作并回传，后台保存/审核，不增加后台执行 skill 或逐次 AI 解读能力；此扩展独立于原 T01–T11 验收。

后续商品形态按 [EXPERIENCE-PLATFORM.md](EXPERIENCE-PLATFORM.md) 扩展网页叙事/卡牌、2.5D、Three.js 3D 和小游戏。T15 区分内容、评估机制、交互模板、主题；T16 先做仍确认单选答案的沉浸呈现，T17 再逐玩法增加排序/分配/分支等协议与评估。当前仅 dimensions_v1 已实现，新玩法不作为原 v1 必需范围。

## 2. 角色与访问面

| 角色 | 可使用范围 | 限制 |
| --- | --- | --- |
| 访客 | 商品目录、详情、公开报告样例、兑换与恢复帮助 | 不能读取完整题库计分规则或私人报告 |
| 匿名权益持有者 | 已领取商品、答题进度、报告、凭码恢复 | 浏览器会话须有效；未绑定码才可匿名恢复 |
| 邮箱账户 | 认证流程、已绑定商品/报告、显式绑定 | 普通账户不是管理员；未验证邮箱不能绑定 |
| 经营者/管理员 | 商品与素材管理、订单/发码、补发撤权、概览 | 服务端角色授权；管理界面隐藏不能替代鉴权 |

消费者与运营路由分开；暂不展示创作者入口。匿名列表与账户列表分开读取，可在界面提示“本机未绑定商品”，登录不自动合并权益。

### 商城信息结构

- 主分类固定初始五类：关系情感、职场工作、自我探索、生活消费、趣味娱乐；商品一个主分类、多个标签，分类可维护。
- 体验类型与题材分开；当前运行引擎只做多维评分/类型报告，不为占位分类开发新引擎。
- 未来交互模板与视觉主题独立于评估机制：Three.js 场景可回传原 questionId/optionId；真正排序/分支/动作等必须注册新答案与评估能力，不能仅增加 experienceType 展示标签就视为已支持。
- 商品卡字段：封面引用、名称、短钩子、摘要、价格、预计耗时、题量、标签、领取/进度状态；布局由正式 UI 决定。
- 推荐由经营者设置，最新按发布时间；没有真实数据时不显示销量、热度排名或“多少人测过”。
- 搜索/筛选/排序参数可写入 URL，刷新和浏览器返回保留条件；过滤后统计与分页使用同一条件。

### 通用状态

所有页面至少处理 loading、empty、error、success；私密功能还需 unauthorized、expired、revoked。保存请求区分保存中、成功、失败/待重试，成功以服务端确认的版本为准。统计出错不丢弃已保存回答，也不阻断继续答题。

## 4. 占位内容与环境隔离

占位数据约定见 [PLACEHOLDERS.md](PLACEHOLDERS.md)。使用完整的商品/版本/题目/报告结构，以便替换内容而无需改接口。

- 每件占位商品标记测试用途，测试站点明显显示“演示内容，不用于购买”；购买按钮不得指向假店铺或伪造订单入口。
- 可以在隔离测试环境走真实数据库和 API，不能仅用前端常量冒充数据驱动。
- 测试答卷可验证统计，但不能进入任何真实商品的生产汇总。环境、数据来源与是否演示须明确，演示比例也要标识。
- 生产公开目录不列出占位商品；管理员可在受保护预览中查看。测试发布状态与正式发布使用同一版本机制，但允许发布的环境不同。
- T01–T10 的平台验收使用占位内容；正式题库、双平台封面/视频/文案和实际购买在 T11 验收。

## 5. 关键业务规则

### 版本与评分

- 发布版本不可原地改题、选项、规则或报告模板；调整生成新版本。已开始答卷与历史报告仍使用原版本。
- 同一版本同一组有效回答得到相同结果。评分与完整报告在后端生成，前端不能收到私有权重、完整结果模板或其他人的报告。
- 后续报告把结构化结果、叙事内容和呈现模板分别管理，配套商品情绪/理解目标与风格；新增章节/格式通过版本化契约实现，创作设定不修改旧快照事实，也不引入实时 AI 解读。
- T05 使用每题有效分值范围归一至 0–100、题目/维度权重加权均值；类型阈值比较精确分数，展示保留两位小数。题量和维度均来自版本配置。
- “不适用”、缺失维度、阈值边界和题目完整性按配置校验；不能因某个维度缺答案就伪造分数。
- 权益锁定可用的商品版本，版本升级规则显式定义；下架隐藏新销售/领取入口，保留合法旧权益的答题和报告访问。

### 兑换与归属

- 默认每码一商品一次报告；开始答题不扣次，报告成功生成才扣次。重复领取/提交、断网重试不增加权益或重复扣次。
- 码采用安全随机值，数据库保存摘要；完整码只在生成/交付时受控显示或导出，不进日志、事件、分享卡或 URL。
- 未绑定码再次输入恢复原权益；首次兑换截止时间不提前终止已经领取的报告保存期。
- 匿名会话用安全 Cookie；后端对每次读取/写入检查归属、撤销及到期。不能仅凭答卷 ID 或报告 ID 访问。
- 绑定要求已验证邮箱、有效匿名会话与对应兑换码，并由用户确认；同一权益只能绑定一个账户。绑定后旧匿名会话失效，码不能给其他匿名/账户访问。
- 补发须核验订单，新码承接原权益、次数、答卷和报告，旧码及旧会话作废；不能解除既有账户归属。
- 退款撤权对匿名与已登录账户都生效。报告删除不会重新授予次数，删除的内容不能凭码/登录恢复。

### 统计

- 回答分布分母为该版本题目的其他有效答卷回答份数；结论分布分母为该规则版本的其他有效完成答卷份数。匿名码不能证明自然人去重，界面使用“有效回答/答卷”。
- 当前答卷的贡献从“其他参与者”口径中排除。每答卷每题只贡献一个当前答案；修改替换贡献，重复请求不加计数。
- 结论仅在首次报告完成时贡献一次，新旧版本不混合。拟用 20 份作为展示门槛，对两种分布分别判断；少于门槛显示不足，空样本显示暂无。
- 单题保存与计数更新、报告生成与权益消费/结论贡献使用数据库事务及唯一约束。统计展示失败可重试，不改变答案和固定计分规则。
- 无效答卷剔除同步修正聚合；删除/数据保留策略另见下节，不能在删掉原始回答后依赖它重新计算历史报告。

## 6. 数据模型与接口边界

### 模型分组

| 模型组 | 必需数据与约束 |
| --- | --- |
| 目录 | categories、tags、products、product_tags；slug 唯一；价格以最小货币单位存储；测试用途显式标记 |
| 配置 | product_versions；题目/规则/报告模板、版本号、发布状态；已发布配置不可变 |
| 交付 | orders、redemption_codes、entitlements、access_sessions；订单平台＋引用唯一，码摘要唯一；权益版本、次数、各期限和归属 |
| 账户 | users、entitlement_bindings；Supabase 用户 ID 唯一；角色由后端管理，业务库无密码 |
| 测试 | attempts、attempt_answers、reports；答卷/题目唯一；回答修订号，报告/答卷唯一；保存生成结果 |
| 统计 | question_stats、result_stats；按商品版本/题目/选项或类型聚合，记录真实分母；演示数据隔离 |
| 运营 | campaign_assets、campaigns、events、admin_audit_logs；素材版本与来源，去重事件，必要审计 |

T12–T14 规划在现有商品/素材模型上补充共享选题说明修订、文件/上传会话、素材/题库草稿修订、跨内容引用、带 domain 的 skill 与版本/绑定、制作记录及 MCP 凭据，细节见 CONTENT-BACKOFFICE.md。题库与模板继续以 `ProductVersion.configuration` 为事实来源，引用单题需固定版本/questionId，文案块需固定修订/blockId；消费者个人报告仍是私密快照，不混入内容制作范围。这些新增实体尚未迁移。

商品 `draft → reviewed → published → archived`；兑换码 `issued → claimed`，可到期或撤销；答卷 `started → submitted → completed`，失败重试不创建第二份报告；权益 `anonymous → account_bound`，另独立处理到期/撤销。素材审核状态独立，不把“视频已上传”当成商品已发布。

### API 契约草案

具体字段/校验在 T02 固定，对外错误使用稳定错误码，不用自然语言字符串驱动页面逻辑。列表支持分页、数量上限与合法排序枚举；私密接口统一校验访问上下文，不信任请求里的用户 ID。

| 接口范围 | 主要能力 |
| --- | --- |
| `GET /api/categories`、`/api/products`、`/api/products/:slug` | 公开目录、筛选/排序、详情与经过筛选的样例；不泄露完整配置 |
| `POST /api/redemptions/claim`、`/api/redemptions/recover` | 领取或恢复；错误不泄露账户邮箱/订单内容 |
| `GET /api/session/entitlements` | 当前有效匿名会话的权益/进度列表；不包含账户已绑定商品 |
| `POST /api/attempts`、`GET /api/attempts/:id/questions` | 创建/恢复当前版本答卷，加载题目和已有回答 |
| `PUT /api/attempts/:id/answers/:questionId` | 保存/修改，修订校验，返回保存状态与群体反馈 |
| `GET /api/attempts/:id/feedback`、`POST /api/attempts/:id/submit` | 已答题反馈，幂等评分/完成；反馈不可在首次作答前读取 |
| `GET /api/reports/:id`、`DELETE /api/reports/:id` | 所属权益报告读取/删除，不返回永久公开私人报告地址 |
| Supabase Auth SDK/API | 注册、验证、密码登录、找回、退出、刷新；不另写密码系统 |
| `GET /api/me`、`/api/me/entitlements`、`/api/me/reports`、`POST /api/me/entitlements/bind`、`/api/me/redemptions/claim` | 账户角色、权益/报告列表、显式绑定或账户领取 |
| `/api/admin/*` | 分类、商品/版本、素材、订单/码批次、补发/退款、数据概览；全部管理员鉴权 |
| `/health/live`、`/health/ready` | 进程存活与依赖就绪；不公开密钥或连接串 |

发布校验、报告渲染、素材存储等服务分别作为 NestJS 模块/适配器，首期仍是一个后端服务。管理配置采用结构化输入或校验后的 JSON 导入，首期不做可执行脚本编辑器。

### 期限、删除与未知决策

开发环境可以配置例如首次兑换 30 天、原始答案 7 天、报告 90 天；这些只是联调值，不能显示成正式承诺。自动清理不得删除仍进行中的答卷；原始答案清理后保留已经生成的报告快照，完整报告不再依赖答案表重算。

测试环境先实现清理预演、报告删除及必要交易审计；正式保留期、删除后是否保留不可回溯汇总、账户注销时未消费权益的处理在 T11 前确定。正式注销政策未定时，提供支持入口，不做隐式解绑或让历史码变回匿名可领。

T05 演示的主动删除清空报告快照并保留墓碑，不返还报告次数；原始答案与有效匿名汇总暂保留，以支持退款剔除和清理预演。预演只输出到期记录的 ID/期限/份数，不修改内容，排除进行中的答卷；尚未提供实际原始答案自动清理或整账户抹除。

## 7. 非视觉实现要求

- 后端对邮箱身份、已验证状态、管理员角色及权益归属分别校验。Prisma 不自动继承 Supabase Auth/RLS 的用户隔离。
- 本地使用 PostgreSQL；Supabase 会话池、TLS、迁移账号/运行账号、连接上限按已选架构实施。业务表不修改 auth schema。
- Worker 同域转发 API，保留 Cookie/认证头/状态码；私人响应禁用公共缓存。容器磁盘不保存唯一业务状态。
- 环境配置与密钥管理、错误码、请求追踪、健康检查、冷启动提示、限流、CSRF/来源防护及必要上传校验需独立于 UI 实现。
- Auth 邮件经 Supabase→Resend；平时密码登录不发信。使用测试身份的单元/集成测试不得开放生产绕过验证接口。
- 素材读写通过接口适配：本地测试可用目录，公网部署使用 R2 或已选择的持久化对象存储。不能将云容器临时磁盘当文件仓库。
- 关键验证聚焦并发权益、绑定、状态撤销、版本、评分边界和计数一致性；不为纯颜色/间距变化编写无价值测试。

## 8. 主平台 v1 验收

以下为完整平台验收条件。分阶段先验收本地 API、数据库、功能页面及对应权限测试，云端邮件、公网和目标内置浏览器项单独保持待验收；本地功能版完成不等于公网或商业上线完成。

1. 真实数据库驱动商城和运营接口，搜索/筛选/推荐/分页可用；占位内容被明确识别为测试内容。
2. 从测试订单发码 → 匿名兑换 → 逐题保存/反馈 → 报告 → 原码恢复的全流程通过，断网/刷新/重试不重复消费。
3. 邮箱账户完成真实验证与找回；显式绑定后所属账户可跨设备访问，旧匿名/其他账户访问被拒绝。
4. 管理员可发布新版本、维护素材、发码、补发、退款；普通账户不能执行管理操作，撤权即时生效。
5. 正式 UI 覆盖必要页面与状态；手机、桌面及目标内置浏览器可完成核心流程。
6. 公网测试链路、冷启动、迁移、备份恢复、私密缓存规则及邮件异常经过验证。云配置未就绪时只能验收本地功能版，不能宣称公网平台已完成。
7. 正式商品与销售在 T11 单独验收；M5 平台完成无需先做完三款正式内容或每日生成任务。

新增后台按 M7 独立验收：同一选题四类内容可维护与导出，四类 skill 库各有演示 skill，其中一库有两个版本；经独立 MCP 读取/保存后，视频引用指定两道题及文案 hook/cta，网页可定位来源和实际使用快照。更正文案仅提示相关下游复查，旧成品不变，采用组合经校验固定；领域越权、失效引用和旧修订被拒绝，重试不复制。云文件与远程接入分别由 T09/T14-C 验证。

多形态体验另验旧商品兼容、固定内容/模板/资源版本、同选择输入相同评分、场景中断恢复与同内容回退、移动端加载和操作。新答案/游戏评估逐玩法验证合法性/完成、幂等消费、报告和统计，不能用 3D 画面演示代替服务端玩法验收。
