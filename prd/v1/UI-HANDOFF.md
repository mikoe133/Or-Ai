### T08 已联调行为

- 商城的搜索/分类/AND 标签、价格/时长/类型、排序/分页由 URL 驱动；标题和正文长文本换行，缺失/不可访问封面明确提示。功能区使用不透明浅色底，手机导航保持深色底，390px/1440px 可读性和横向溢出检查通过。
- 答题以服务端保存结果恢复进度，未确认选择不能继续；冲突重读，断网保留未保存状态与重试意图。统计 empty/insufficient/unavailable 分别展示，反馈失败不阻断已保存答案。
- 报告将 null 显示为信息不足，0 分仍为 0；到期/撤权/删除后不渲染旧内容。分享 PNG 仅包含白名单摘要，完整声明随长文自动增高；删除需显式确认且不返还次数。
- 账户绑定需单独勾选确认，登录不合并匿名列表。退出、切换与跨标签页变更清除私密查询；恢复窗口先重新检查访问状态。未配置 Auth 如实提示；本地账户/后台功能由隔离身份与真实业务服务验证，真实邮件仍待 T09。
- 后台拆为概览、商品/配置、素材、订单。编辑保留 expectedRevision/requestId，冲突可刷新；新文件未校验或表单未保存时禁止审核/采用，上传中锁定输入。完整交付码仅在本次响应中显示和主动保存，隐藏/刷新后不恢复。

22 项浏览器流程与 198 项单元/集成测试通过。此记录仅完成 T08 功能与基础可读性验收；正式视觉、图表、弹层、动效和完整设计状态仍按 T10 核对，T12–T17 后台/skill/MCP/体验扩展继续待开发。

## 关键交互必须在设计中体现

- 访客可以直接兑换，不要求先注册。邮箱注册/验证是账户归集流程，登录不会自动绑定本机商品。
- 匿名列表与账户已绑定列表可清楚区分；绑定按钮要表达绑定范围和后果，不能把普通登录按钮当绑定确认。
- 每题先确认并保存，再展示其他有效回答与完成结论，两种统计各有样本量。桌面侧边、手机下方/抽屉的细节在正式图中确定；统计失败不挡住下一题。
- 保存失败时不显示“已保存”；恢复、冷启动、到期、退款撤权与邮箱发信失败均有明确反馈。
- 保存返回 attemptRevision 和单题 revision；后续提交用整体修订。409 冲突先重读进度，旧重试不能覆盖新选择；完成后答案不可修改。
- GET 反馈必须携带 questionId，并先保存该题。保存成功但 feedbackStatus=unavailable 时显示回答已保存、统计可重试；empty/insufficient 分别显示暂无/不足，回答与结论使用各自 sampleSize。反馈只展示标准标签和汇总，不展示他人的报告。
- 报告分数 null 显示信息不足，不能显示零分。删除以 JSON requestId 调用并处理 204 空响应，告知内容不可恢复且不返还次数；410 区分报告删除/报告到期/权益到期，不尝试用旧缓存重新显示报告。
- 兑换前初始化 session/context，CSRF 只保存在页面内存；403 页面授权过期时重新初始化再重试，完整兑换码不写 URL 或本地持久化。匿名 authenticated 与邮箱登录状态分别显示。权益页可展示到期元信息；报告已删除/到期不能显示为可继续生成，恢复不增加次数。
- 商品题材分类与功能导航分开，消费者与运营入口分开；没有数据支撑的热榜/销量组件不绘制为真实指标。
- 分享卡展示结果摘要，不包含码、账户邮箱或私人报告凭据；账户注销政策未确定前采用支持入口。

## 建议随设计稿提供的信息

1. 商城桌面与手机布局，导航和筛选的折叠方式。
2. 字体、字号、颜色、背景、边框、圆角、间距、图标来源及图片比例；先作为主题变量接入，避免散落硬编码。
3. 表单、按钮、商品卡、分页、弹窗/抽屉、通知、统计图等公共组件的默认/悬停/禁用/加载/错误状态。
4. 登录、兑换、答题、报告与运营页面的关键操作位置；未提供的页面保持临时功能界面，单独列为待设计。
5. 交互说明：点击后去哪里、是否打开弹窗、如何关闭/返回、手机触摸操作、慢网下如何提示。

以上是接入时核对的交接清单，不能将“已有双端首页稿”自动视为所有页面已设计。设计按页面读取接入；先完成本地功能与视觉，再做 T09 的真实云端认证、存储和公网验证。
