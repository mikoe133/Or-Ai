## 完整数据结构

每件商品都有 slug、名称、短钩子、摘要、主分类/标签、测试价格、题量、预计耗时、体验类型、主题键、封面引用、公开样例、配置版本及测试用途标记。

每个版本含题目 ID、选项 ID/文本、维度、仅后端可读的计分规则、类型阈值和报告段落；至少包含一个“不适用”选项，明确缺失维度的返回方式。种子脚本在校验通过后才能发布测试版本。

演示报告保存类型名称、2 个维度分数、简短解释和一条建议；不宣称专业判断。`demo-partner` 已保留 v1/v2，v2 改变首题范围、中间选项计分和解释；当前目录指向 v2，历史答卷/报告锁定 v1。

## 联调状态样本

| 数据组 | 需要覆盖的状态 |
| --- | --- |
| 商品 | 草稿、已发布测试版、下架、无封面、长标题、空分类、多标签 |
| 订单/兑换码 | 未领取、已领取、首次兑换过期、撤销、核单补发；不使用真实订单/买家资料 |
| 权益/会话 | 匿名待开始、进行中、已完成、账户绑定、报告到期、退款撤权、失效会话 |
| 答卷 | 部分回答、全部回答、修改冲突、重复提交、跨版本恢复、不适用维度 |
| 群体统计 | 0 份、门槛以下、达到门槛、当前答卷被排除、未完成不计结论 |
| 邮箱账户 | 未验证、已验证、普通用户、管理员；真实收信用经营者拥有的测试邮箱 |
| 素材 | 占位封面、示例脚本/文案、未上传视频状态；不是实际视频交付物 |

当前实现含三款已发布主占位商品、额外草稿/下架状态商品、五类和四标签。工作商品无封面，社交商品有长标题；生活/趣味分类为空。两平台均有封面/脚本/文案元数据和未上传视频的 draft 状态。

全新隔离 seed 的伴侣 v1 首题有 22 份有效回答、21 份有效完成答卷，v2 为 0；工作商品不足 20。聚合由数据库中的演示回答/完成报告推导。T05 已验证排除一份已完成答卷后，首题回答分母 21、结论分母 20；排除一份未完成回答后为 21/21。真实答题会更新当前库计数；上述是 fixture 基线。新版本不混入旧样本，无样本或不足时不编造百分比。

seed 报告是合成的联调快照；T05 API 新生成的报告由通用评分器计算，三款占位都已完成实际保存、提交与原码跨设备恢复测试，并验证并发只扣一次、回答冲突/替换、删除不可恢复与退款剔除贡献。邮箱“未验证/已验证”仍是测试场景元数据，业务库不将其作为认证证据，也没有生产登录绕过；真实收信、绑定和账户跨设备验证在 T06 验收。T02 样本本身不代表行为通过。

开发者需要可用测试码时，使用受保护的 `pnpm delivery:manage` 创建自己的 DEMO 测试订单并首次导出秘密文件；seed CLI 不显示既有完整码。发码/补发文件为 0600，不放入 Git、页面 URL 或聊天。真实运行验收创建的自有测试订单已退款撤权，原 seed 状态未改写。

## seed 与替换规则

- seed 可重复执行，稳定 ID/slug/upsert，不重复创建码、订单或统计；完整码/会话令牌仅首次创建时返回库函数调用方内存，CLI 不输出，不保存在文本或日志。重复 seed 不能恢复秘密；数据库只保存摘要。
- 只允许向明确的开发/测试目标写入；生产默认拒绝装载演示商品/答卷。生产管理员预览与公众目录分开。
- 接口契约不能依赖这三款的名字、题数或固定维度。前端通过字段渲染；正式商品用新配置/新版本加入，不能覆盖已发布测试版快照。
- 不编造销量、好评或真实用户标签；测试与生产事件、统计、文件空间分别隔离。

命令为 `pnpm db:migrate` → `pnpm db:provision` → `pnpm db:seed`，需先启动真实本地 PostgreSQL、构建契约和设置显式目标。目标检查与权限说明见 [DATA-MODEL.md](DATA-MODEL.md)；前端字段与示例见 [API-CONTRACTS.md](API-CONTRACTS.md)。
