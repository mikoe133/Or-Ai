# T16-A：社交电量小屋试点

2026-10-21。T15-B 界面已获用户批准，小屋/手记和配套试点内容已实现并通过技术验证，当前停在本批 UI 审核；这是本地设计/业务样例，尚非正式商品。获批后继续 T10-L，真实设备证据独立补齐；云端另行批准。

## 能力与创作约束

为单人自我观察提供一间安静的 2.5D 小屋，用场景中的明确选项回答最近一周的社交恢复与边界表达问题。目标是允许自己需要休息，并找到一个可以尝试的小行动。画面、报告、封面与文案共用纸本手记、暖白/灰紫、窗光与座椅意象。题目使用直接语言，不从选了哪件家具、操作路径或反应时间推断人格。

试点方法选择：信纸般的留白、平面等距插画和明确的紫色选中态；桌面左右分栏，手机先看房间再读完整选项。房间标记与选项列表对应同一 optionId，选中和保存分开。无自动播放声音、拖拽、摄像机或持续动画；键盘、触摸和减少动态必须可用。

## 实施契约

- 新增静态注册组合 `quiet-room@1` + `field-notes@1`，继续接收 single_choice_v1 和 report_content_v1；保留 DOM/旧报告组合。混搭、未知版本与超过四选项的房间草稿不可审核发布。
- 房间使用可信本地 SVG/DOM/CSS，无 Three.js、外部字体、任意 HTML/脚本或新依赖。每题 2–4 个选项；资源可选，最多两张 PNG/JPEG/WebP、单张 512 KiB、合计 1 MiB。原 DOM 模板预算不变。
- 房间对象通过固定 sceneId/objectId 映射到原 questionId/optionId。所有保存/恢复/评分/报告/次数/统计与撤权由原后端完成；同一配置同一输入与 DOM 结果一致。独立商品版本隔离正式模板统计。
- 手记报告只重排服务器的结论、维度、解释、建议及声明，不新增客户端评分或诊断。缺失维度和空总分明确展示，保留相同内容的简化回退。
- 管理员可选择新组合，继续走 T15-B 的固定设定、方法、资源、草稿、校验、人工审核与精确发布。MCP 默认上下文保持兼容，显式请求新模板能力时才增加注册表信息。
- 增加显式 `/preview/experience/quiet-room` 设计样例，可练习选择/确认及查看独立标注的报告排版样本；不创建实际答卷，不根据本地选择计算真实报告。真实业务验收使用隔离 PostgreSQL、权益和同一运行组件。

## 预算与设备证据

开发验收目标：1440×1000 桌面、390×844 手机视口和 393×852 Android 视口；原生键盘/触摸、减少动态、模块/图片失败、刷新恢复、过期/退款拒绝和单次消费。模板新增 JS+CSS gzip 预算 45 KiB，资源至多 1 MiB，封面预算 400 KiB，静音宣传样片预算 3 MiB。截图/录像使用本机浏览器与合成内容。

实际手机及微信/小红书等内置浏览器当前没有设备证据；模拟视口不冒充真机。对应验收保留待验证，UI 审核时明确报告。正式题材/文案、量表依据、物理设备性能与商业渠道在正式商品前另验。
