# 后续任务执行顺序

日期：2026-10-16。状态：T06-O 已验收，下一批次为 T12-A；其余后续任务待执行。本文是 T08 之后执行顺序的唯一入口；需求和字段分别留在 PRD、内容/体验约定中，具体复选框留在各 task 文件。原 T 编号保留，执行顺序按本表，不按文件编号排序。

## 当前起点与排期原则

T01–T05、T06-L、T07、T08 本地必需项已验收。现有 NestJS/Prisma/PostgreSQL、React/Vite、Tailwind 3.4、商品版本、订单/权益/报告和文件服务继续复用。T06-O 已补 25 项配置/运行栈检查和 11 项真实本机 Auth 浏览器验收；原后端 158＋前端 40 项测试、22 项业务浏览器流程本轮回归通过，详见 PROGRESS.md。

后续先形成可用的内容制作链，再丰富体验与报告形式，最后统一接入正式视觉和云端。平台宗旨始终是提供情绪价值、加深自我和关系理解；每款商品共用一份固定修订的创作设定，题目/体验/报告/封面/视频/文案按该设定配套制作。

固定规则：

- 已发布商品、答卷和报告保持原版本；新内容用新修订/新版本，不覆盖历史结果。
- 四类内容、四类 skill 和四领域 MCP 独立；同一商品通过明确版本引用连接，不能只靠风格标签或 latest。
- 私人答卷/报告与经营者内容分开；宣传制作不取得消费者数据或完整私有计分的默认权限。
- 首期由外部 AI 制作后回传；skill 保存、MCP 上传不等于后台执行模型、渲染或自动发布。
- 先支持已有单选评估的不同呈现；排序/分配/分支等新答案类型单独实现和验收。
- 下表是推荐排期。T15/T16、完整内容后台和远程 MCP 仍是独立扩展，不增加原 M5 平台/M6 商业验收的强制前置。

## 各批次的可执行边界

### 0：本地实际操作环境

本批次已验收。按 [T06-O](tasks/T06-accounts.md#local-operator-setup) 接入本机 Supabase Auth 和 Mailpit，认证数据与业务库隔离，保留数据卷和稳定密钥。真实注册/验证后的用户经已有 `admin:manage` 授权，普通用户拒绝、管理员操作和撤销、找回、重启及配置停用/恢复均有实际证据。可重复步骤见 [AUTH-SETUP.md](AUTH-SETUP.md)。

退出条件：经营者能在浏览器操作现有基础后台，本地邮件、回调和管理员权限有实测记录；之后新增内容页的实际管理员操作由 T12-B/C 回归，不作为 T06-O 的退出条件。停止服务可恢复原环境，不能重置业务库或加入绕过登录的接口。本阶段不证明 Resend/外部邮箱或公网认证已通过。

### 1–3：先完成 T12 内容链

上下文入口：[内容约定](CONTENT-BACKOFFICE.md)、[创作设定](PRODUCT-CREATIVE-SYSTEM.md)、`packages/contracts/src/admin.ts`、`apps/api/src/operations`、`apps/api/src/catalog`、`apps/web/src/admin`。复用 Product 作为内容项目、ProductVersion 作为题库/计分事实来源、现有 AssetFile/上传服务作为文件底座。

- **T12-A：**先固定新 DTO/向前迁移及服务。统一 creativeProfileRevisionId 与 brief 的含义，确定素材不可变修订、questionId/blockId/sceneId、引用/输入快照和制作记录；先能通过 API 保存和读取同一商品的固定依据。task `.1/.5/.8` 在此只交付基础契约与底座，交互及成套规则留后批次，不提前勾选整项。
- **T12-B：**接入工作台、创作设定、题库/报告编辑、封面/视频真实文件和文案块/分镜。题库发布继续走既有校验；此时采用的报告保持现有严格 schema 与兼容图文模板。新章节/叙事方案用独立、版本化的报告方案草稿 schema 保存、校验与编辑；T12 完成该内容草稿能力，T15 再实现新运行投影、renderer 与发布兼容检查，不将 HTML/未知字段塞进旧报告。
- **T12-C：**完成引用校验/上下游反查、差异与复查状态、固定采用组合、导出、制作来源和临时文件清理。覆盖已有历史素材的兼容读取和实际可播放视频；上游更新不改变旧视频/报告。清理先预演，只处理已确认过期且无引用的临时文件。

退出条件：一款演示商品有明确情绪/理解目标及完整四类内容，使用现有兼容报告方案完成试读/预览/采用；视频实际引用两道题和文案 hook/cta，修改文案可反查受影响视频，旧稿不变。新报告方案草稿的结构校验/编辑单独通过，但未支持的运行形式不可采用；不等待 T15 新 renderer 才关闭 T12。按 task `.10` 完成验收，此阶段 skill 来源可明确为空，避免与 T13 形成环依赖。

### 4：再加入 T13 skill 库

上下文入口：[T13](tasks/T13-style-skills.md)、T12 已落地的修订/文件/制作记录服务。分两批交付：先 skill 元数据、包/附件校验、四库 CRUD 与版本生命周期；再按商品设定绑定、来源追溯、领域授权 API 与演示验收。

assessment 区分题目/规则设计和报告写作用途；cover、video、copy 各有自己的指令与输入输出。参考文件导入/导出需要通用受控附件用途和校验，不将 Markdown/文档伪装成图片，也不在后台执行附件脚本。扩展文件服务时保留原媒体校验。

退出条件：四库各有演示 skill，一库存在两个可追溯版本；旧/归档版本及引用仍可读取，错领域/错形式绑定被拒绝。升级 skill 不改变历史制作记录；只有保存读取能力通过，不宣称后台已运行生成任务。

### 5：T14-L 连接外部制作工具

上下文入口：[T14](tasks/T14-mcp-ingestion.md)、T12/T13 业务服务与真实本地管理员环境。先交付机器授权适配、权限/撤销、上传票据和 stdio 基础；再交付四领域工具、最小上下文/引用校验、制作来源及实际客户端联调。工具层只调用受控 API，不另建规则或直接写数据库。

退出条件：实际客户端分别连接 assessment/cover/video/copy，读取各自 skill 和同一设定的必要输入，上传真实文件并保存为网页可见的同一草稿。用一个“上传已成功但客户端未收到响应”的用例验证幂等恢复，用撤销凭据验证上传完成立即被拒绝。发布、发码、退款和物理删除不开放给首期 MCP。

### 6：T15 建立多形式兼容底座

上下文入口：[体验约定](EXPERIENCE-PLATFORM.md)、[T15](tasks/T15-experience-runtime.md)、现有 `runtime` 与报告快照。先做 T15-A 基础：版本化体验清单、DOM 单选宿主、资源用途、报告 renderer 注册、确认/恢复/回退及旧商品回归；后做 T15-B authoring：内容后台配置和体验/报告制作的 skill/MCP 扩展。

退出条件：旧商品和历史报告继续可读；同一标准选项输入的评分一致；刷新/资源失败/过期/退款后状态正确。新报告内容 schema 和 renderer 双向校验兼容性，不能仅因上传了新主题就宣布新报告形式可用。T15 基础通过可启动 T16-A，整项完成仍要 T15-B 通过。

### 7：T16-A 只做一个轻量试点

退出条件：真实权益→互动选择→确认保存→刷新恢复→配套报告→退款撤权完整通过，具备触摸/键盘、减少动态与简化界面。报告、封面、视频和文案共用该商品设定并经试读。只复用单选评估，不加入路径/反应时间推断，也不一次制作多款或同时引入 3D。

## 每批次的验证与暂停边界

实现前读取该 task、本文对应批次和相关契约。按实际问题补测试，完成本批后记录服务/页面/数据证据和遗留，不因某个子批通过就关闭整份 task。改 schema 仅追加向前迁移；发布保持新旧版本并存，失败禁用新入口/回退应用，不 reset 数据库或覆盖历史文件。

需要改代码的批次根据改动运行已有 `pnpm typecheck`、`pnpm build`、`pnpm test`，浏览器操作改变时扩展 `pnpm test:e2e`；数据库和文件改动另验迁移、范围权限、幂等/修订、历史引用与清理。不能以这些现有命令通过代替尚未编写的新能力验收。纯规划修改只做文档链接、编号/依赖和状态一致性检查。

本地 Auth 运行方式已在 T06-O 固定，见 AUTH-SETUP。后续技术选型/产品条件在对应任务开始前固定：报告 schema/兼容 renderer（T12-A/T15）、skill 包格式/附件限额（T13）、MCP SDK/客户端兼容（T14）、试点题材/设备/预算（T16）、云账户/预算/域名（T09）、正式商品与政策（T11）、首个新玩法及评估依据（T17）。这些待定项不阻塞无关的前置开发，也不提前写成已确认事实。

用户在规划后授权执行下一项，本轮完成 T06-O 后停止，未进入 T12。下一执行入口为 T12-A；未创建 Goal、自动化、云资源或公开部署，不自动扩大到其余批次。
