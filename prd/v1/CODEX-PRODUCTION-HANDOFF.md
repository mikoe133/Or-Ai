## 编排取舍

默认采用同一商品 run 的统筹入口，按固定计划 DAG 推进；没有子代理时顺序执行完全可行。有限短期并行适合明确独立的模块，不能靠开四个聊天自动获得事务或领域隔离。独立长期任务仅在工具/机器隔离或长媒体作业需要时拆分，并交换 run/module/固定输入/回执及外部 jobId。当前这一开发轮继续单 Agent，不启动这些外部任务。

| 阶段 | 固定输入 → 可回读输出 | 依赖与执行边界 | 拟采用的限制（尚未启用作业） |
| --- | --- | --- | --- |
| S0 检索 | 地区/语言/时间窗 → 带源时间或未知、检索时间、链接的候选证据 | 国内/国际可独立整理；无新鲜来源就无选题/无产出，不造商品 | 有界来源数/时长；未知工具费用需人工确认 |

| S2 方法 | 固定计划＋允许的基础库 → 精确方法快照＋商品参数/必要定制 | 模块可独立；优先复用，不反复改写整个共享库；候选方法不自动 ACTIVE | 方法创建额度；定制与基础版本均留存 |

## W1/W2 实施约定（已本地验收）

持久 run 固定 product/plan/profile 与有限策略；模块尝试固定方法、依赖记录和摘要。短期认领和事件修订用于同阶段排他及过期执行者隔离；认领 token 仅存摘要，回执不保存 bearer/票据。外部作业只记录 provider/jobId 与申报状态，不托管 worker、不发起生成或轮询收费服务。

至少区分 waiting_input、producing、uploading、validation_failed/failed、saved_draft、cancelled；pending_review/returned/retained 从 P4 的真实固定审核记录推导，并返回对应记录 ID。方法完成不能冒充产物完成；没有实际产物的失败也能记录原因。saved_draft 必须重新核对同模块的真实制作记录、精确方法/输入与实际文件，保留 verifiedAt/校验范围，不能推导平台执行过模型。

相同 runKey/输入的真正重试恢复原记录；新计划/变体另建明确业务身份。两个客户端认领同模块时只允许有效写者；过期尝试的事件/完成被拒绝。已成功模块不自动重建；上游变化标需复查。响应不明先读回执/上传状态/jobId，不重新付费生成。已用官方 v2 SDK 2.3.1 客户端两个独立进程先后退出/启动，从持久回执恢复同一 run/attempt 与原合成 jobId，未新增尝试或实际生成作业。这是业务 SDK 恢复证明；未运行 CLI 推理或桌面无人值守恢复。

成本和 token 只能区分外部申报、实际工具观测与未知，平台不冒充账单计量。次数/并发/认领时长可以服务端强制；实际费用、模型档位小样本比较与无人值守仍需单独批准配置。没有确定规则的热点过滤、版权策略等只保留可配置建议，不宣称已实现。

W6 追加的阶段归属固定为 assessment→S3、copy/experience→S4、cover/video→S5；阶段时长从首次尝试计起，额度仅控制新认领，不预留预算或中止外部作业，过期拒绝写回执。详见 [精确策略与兼容边界](EXTERNAL-PRODUCTION-RUNS.md#限制与费用)。S0–S2/S6/S7 暂无服务端阶段预算执行器，不能把制作阶段策略称作整个 S0–S7 的自动调度。
