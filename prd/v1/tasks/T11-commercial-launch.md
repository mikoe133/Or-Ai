# T11：正式商品替换与商业上线（后续）

状态：后续待执行，不阻塞 T01–T10 主平台建设。依赖：平台验收、正式内容与实际渠道条件。UI 依赖：平台 UI 已完成。

## 执行批次

位于 [ROADMAP.md](../ROADMAP.md) 顺序 12，在 T09＋T10-V 关闭原平台验收后执行，先做一款正式商品。

- T11-A：`.1–.4` 与 `.7` 的试读准备，确定内容/配套素材、正式政策和真实渠道条件；使用已实现形式，不在售卖阶段临时加入未验证的新玩法。
- T11-B：`.5–.7` 的上线前检查、按实际授权开展的真实订单/售后与用户价值反馈；测试环境证据、演示内容或后台齐备状态不能代替真实商业验收。

默认以单款试运营结果决定是否扩品；T16-B 的 3D 和 T17 新评估留后续，不作为首款销售的必要条件。T12/T13/T14 已启用时沿用采用清单与来源；原 M6 不因远程 MCP 未启用而阻塞。

## 子任务

- [ ] T11.1 按平台情绪价值、自我/关系理解宗旨确定商品创作设定和正式题库/计分/报告，人工试测；明确单人视角或实际支持的参与方式，形式/风格/报告配套，新版本替换占位且不覆盖历史快照。
- [ ] T11.2 明确正式价格、兑换次数/截止时间、报告保存期、数据删除/汇总保留、售后与账户注销权益政策，配置对应清理及支持流程。
- [ ] T11.3 为正式商品完成分享卡、双平台封面、钩子视频成品/脚本与两套文案；真实材料替换占位关联。已启用 T12/T13 时从固定商品版本/素材修订导出并记录 skill 来源；正式内容仍需人工审核，后台已存文件不等于素材已可公开销售使用。
- [ ] T11.4 核验实际平台类目、外链/访问说明、卡密交付/核单与售后路径；不按臆测规则公开销售。
- [ ] T11.5 检查生产目录/事件/统计没有占位商品或测试答卷；复核邮件/账单/容量监测、备份、隐私说明与支持入口。
- [ ] T11.6 完成一笔平台允许的真实购买/兑换/报告交付，验证恢复、补发、退款与撤权，记录完成率、售后和单单贡献。
- [ ] T11.7 对正式商品进行成套试读/体验，记录用户是否感到被理解、获得具体自我/关系发现和可用表达/行动建议；与转化/完成/退款指标分别记录。传播承诺、实际交互和最终报告经人工核对，双方对照仅在对应参与/分享能力实际支持后宣传。

## 交付与验收

正式商品包与真实订单交付记录。买家明确知道内容、次数与保存期，完成后可按承诺读取报告；经营者能处理售后。只发布测试商品不算商业上线。

经营者内部风格 skill 的保存/版本管理已独立规划为 T13，内容后台与 MCP 接入见 T12/T14；这些可以在云部署和商业上线前本地完成，但不作为 T11 的强制前置。对外创作者模板/skill 自助执行、积分、每日热点/素材生产任务与自动订单同步仍按真实需求另行排期。
