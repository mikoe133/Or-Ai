## T06-O：本地实际操作准备（已验收）

排期见 [ROADMAP.md](ROADMAP-before-replan.md)。T06-L 已完成结论保留，本节补“经营者能实际登录使用后台”的环境与实测，独立于 T06-C 云端认证。它不要求云账户、发信域名或付费资源；配置暂时失败时可继续 T12-A 模型/API 和隔离测试，手动验收保留未通过。

- [x] T06.O1 核对并固定本机 Supabase Auth 的受支持运行方式及本地收件工具，提供独立启动/停止与就绪检查；认证存储与现有业务库/卷隔离，端口不冲突，不 reset 或复用业务 auth 哨兵表。
- [x] T06.O2 配置真实本地 Auth 的前后端 URL/公开 key、本站与邮件回调；稳定服务端加密/签名密钥继续保留，私密配置只入被忽略的 `.env`，不添加业务登录后门或模拟身份开关。
- [x] T06.O3 通过浏览器注册、从本地收件工具验证邮箱并密码登录，在业务库同步真实 Auth 用户；使用现有 `admin:manage` 为该本地用户授权/撤销并留审计，不把 seed UUID 当登录凭据。
- [x] T06.O4 手动及浏览器验证管理员可操作基础后台、普通账户不可操作、退出/撤销立即失效；本地找回/回调与失败状态留实际证据。完成后可为 T14 网页签发受限机器凭据，T14 尚未开发时不宣称已可签发。
- [x] T06.O5 补充 AUTH-SETUP 的可重复操作与故障恢复说明；停止/重启后本地用户、业务数据和稳定密钥保留，环境变更可撤回且不破坏 T08 匿名业务。

退出条件：经营者能用真实本地账户在浏览器使用后台，具有可重复的登录/授权/撤销证据。这里只验本地 Auth 和本地收件，不能勾选外部邮箱、Resend 或公网认证；不重做 T06-L，不阻塞无关内容服务的开发。
