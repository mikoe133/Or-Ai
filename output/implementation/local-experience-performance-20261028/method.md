# 06 本地性能与恢复：执行口径

2026-10-28，起点a4a687a。仅在隔离TEST、合成A/B、当前生产构建及CUA控制的桌面内置Chromium中测量。

## 资源与停止条件

实测Mac16,10，10核、16GiB；memory_pressure报告48%余量，load约2.9。工作盘745GiB余量；Docker 1.89GB余量，原5容器healthy、合计约145MiB。只启一套TEST、一个受测页面，按顺序测量；不构建镜像、不清理不明资源、不改系统资源。余量低于20%、Docker余量低于1GiB、原容器不健康或明显交互失常时停止新增负载，保留已测结果。

## 已定阈值与本轮技术假设

- 已定：首帧3000ms；活动阶段≥30fps；A/B renderer gzip240/220KiB；资源1MiB/512KiB；DPR1.5/1.25；canvas150万/100万像素；三角形14000/8000；draw calls48/32。
- 首帧：分别记录实际WebGL提交并进入ready的时间、必需参考图加载时间，以及之后一次rAF的绘制机会时间。后者作为本轮first usable frame口径，不冒称LCP或精确GPU屏幕呈现时间。
- 冷缓存是同一已启动浏览器中的新文档、禁用HTTP缓存；不声称冷GPU驱动或冷OS。记录本地Nest启动阶段时，区分模块构建、listen和TEST数据准备。
- 基线：桌面、无CPU/网络降速。附加条件：5Mbps下载/1Mbps上传、100ms RTT、CPU4倍降速，仅为受控模拟。两种条件均按3000ms报告，不放宽原目标。
- 计划采样：A/B各在1440×1000、768×1024、390×844，每种条件3次；实际缺样不填通过。
- 活动FPS：有界持续选择或镜头操作，记录真实发生draw的rAF时间与回调耗时；静态空闲不算0fps。若无法取得足够连续绘制样本，只报告耗时和缺证，不伪造帧率。
- 内存原计划未给数值。本轮先固定技术验收假设：20次装卸（5次预热＋15次观察）；每次卸载后零存活场景GPU上下文/资源、零场景绘制；强制GC后末5次JS heap中位数较预热基线增幅≤max(5MiB,20%)；DOM节点/监听器不持续线性增长。此为桌面泄漏筛查门槛，不是生产内存上限或真机证明。
- 测量探针仅由CDP加载，不进入产品包；GL/RAF包装的开销计入样本。GPU资源计数区分显式delete和context loss隐式释放，不保留DOM/原生对象强引用。
