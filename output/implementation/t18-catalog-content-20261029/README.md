# T18 商品目录、内容目录与工作台首批改造

日期：2026-10-29。继承B「精密工具紫」及完整项目anti-ai-web-design Skill；沿用现有React/Vite、NestJS/Prisma/PostgreSQL、路由与版本规则。只改后台；商城用户端、真实云服务、真实权限、日程和内容生产保持原边界。

## 实际基线与问题

在415a353代码上，以同一合成隔离TEST/真实API建立六类表面×1440×1000、768×1024、390×844共18张基线：商品目录、资料编辑、已发布配置预览、内容目录、创作设定、引用与历史。使用独立随机.localhost主机及既有Auth协议替身，不代表真实外部认证或真机验收。

1. 商品/内容目录仍有9px的重复全大写眉题，次级编号和统一紫色状态抢占业务层级；同一商品的archived在两页文案也不一致。
2. 窄屏内容目录的“管理商品资料”换行拥挤，表头与内容列未完全对齐，搜索、空态与计数缺少稳定分区。
3. 13项工作台栏目在手机宽度横向裁切；制作范围和技术明细占满首屏，历史主体不可见。
4. 刷新失败直接移除已有商品行。真实RED见[记录](red/catalog-refresh.json)：缓存原有5行，网络重连读取失败后显示0行。初次加载、空结果与旧目录等待新筛选结果也需要明确区分。
5. 后台把通用错误组件的消费者恢复链接隐藏了，实际缺少清晰的后台恢复入口；已发布配置缺少醒目的固定版本说明。

## 实现

- 商品和内容目录建立一致的标题、筛选、计数/更新目录、结果区、空态和分页层级；减少无意义编号/徽章，状态保留文本并分离语义色。全部商品与筛选结果明确区分，清除筛选与浏览器返回同步控件值。
- 普通刷新失败保留已有数据和未提交筛选；新筛选等待时注明上一份目录，暂时禁用旧商品编辑/内容入口。401/403及身份错误隐藏旧私有展示，不按普通网络失败保留。
- 新增仅后台使用的错误恢复与草稿保留说明，原商城通用错误组件未修改。初次加载/失败和空态都有明确动作。
- 窄屏提供13项原栏目选择器，复用原未保存保护；桌面原栏目顺序保持。压缩制作范围为当前组合/状态/必要警告，把版本依据和注册表放进可展开明细；不改变能力判断或把旧DOM记录冒充Three.js。
- 历史及已发布版本继续固定引用，明确另导入新版本的路径；禁止覆盖/审核/再次发布已固定版本的原有门禁保持。工作台多个请求同时失败时优先处理权限拒绝，稿件/体验请求拒绝也隐藏私有工作区。
