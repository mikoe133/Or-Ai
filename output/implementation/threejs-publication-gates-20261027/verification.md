2026-10-27，T16.C2-B 本地技术范围完成。新体验审核、成套采用和正式发布固定完整商品规划、真实注册的场景/报告配对与精确方法；旧发布版本、权益、答卷和报告保持兼容。此处发布操作仅在隔离 TEST 数据库验证。

## 实现与退出范围

- 项目体验制作稿改用共享注册能力检查，支持实际注册的 Three.js 配对；固定模块、内容和规划摘要。`purpose: authoring` 制作稿不能代替 ZIP/GLB 等原件。原件留存仍不代表可运行或可发布。
- 人工与 MCP 体验稿保存 `productPlanInput`；多体验模块时明确选择，待规划可以存草稿。审核精确追加最新草稿，要求最新完整规划、已实现的必需决定、同内容/设定、注册配对、资源/图形预算和实际文件摘要。
- 共用规则覆盖人工/项目方法、API/SDK、默认/自定义发布、采用和维护 CLI。新发布无体验稿、旧 DOM、小屋、空白/未知 Canvas、错报告、未实现玩法、过量/损坏资源或旧政策方法均不能通过。
- 项目候选保留 `projectMethod: {snapshotId,digest}`，支持尚未启用为全局 ACTIVE 的定制 DRAFT；精确核对基础版本、展开正文和附件。题目/报告方法也必须匹配固定规划，不能借历史组合绕过。
- 新采用清单 v3 固定完整规划、已审核体验、实际 renderer/report 配对和来源，采用不发布。历史 v1/v2 读取与导出保持。注册兼容、人工审核与设备验收分开显示，窄屏失败保留未保存说明。
- 两份前向迁移新增 nullable 规划输入并加强审核/发布数据库约束。运行身份不能直接插入已发布版本或切状态走默认发布；owner 历史恢复仍可用。当前 SQL 配对固定实际已实现的 `reflection-garden@1` / `garden-notes@1`，未来新增模板需同步注册表及前向迁移。
