# T18 素材、订单与操作错误恢复验证

日期：2026-10-29。基线 `f7bdb7466e0e5a5855e73a3b22b01f13200002d8`。本批只完成后台独立子范围，完整 T18、05/06 及商城截图审核边界保持。

## 诊断与实施

按项目 anti-ai-web-design 的 P1–P12/R10，先检查七类页面的三个视口截图，确认以下问题后实施：

1. 素材缩略区占用较大，文字、缺文件与实际媒体缺少明确区分。
2. 多份素材均为变体 A，现有类别/平台/修订信息不足以区分固定商品版本。
3. 素材和订单仍有重复英文眉题、偏小元数据及统一紫色状态，筛选和结果层级没有与已改目录统一。
4. 首次读取与普通刷新失败共用替换式错误展示，缺少保留内容、等待新筛选和权限拒绝的区别。
5. 商品编辑出现本地 JSON 错误后返回列表，旧错误仍残留；有效 RED 的预期错误数为 0、实际为 1。

沿用现有紫色 tokens、中性表面、路由、API 和权限，实际修改：

- 素材/订单目录统一筛选面板、计数、清除、显式更新、空态与分页；控件随 URL 清除及浏览器返回同步。普通刷新保留目录和未提交筛选，读取新筛选时标明旧结果并禁用旧编辑/订单入口。
- 区分文字摘录、未关联文件及预览失败；原生图片失败提供可重试回退，视频保留 `preload="none"`。素材显示真实类别/平台/修订与固定版本 UUID，没有编造商品名或真实素材。
- 新建素材/人工订单的商品选择保持布局与所选版本；搜索等待和失败保留其他表单输入。保留原上传校验、素材审核/就绪/归档和封面采用门禁。
- 订单详情整理状态、登记金额及兑换码记录；保留发码、补发、一次性交付与退款确认语义。详情刷新时暂禁变更操作，503 保留输入，403 隐藏私有区域并清理交付内存/确认状态，恢复后需重新确认退款。
- 在商品、素材、订单与历史修订选择处清理旧操作错误；错误面板按所属目录恢复。正常编辑错误的返回使用页面自己的状态清理，权限拒绝的恢复重新导航并核验身份，不能仅清错误恢复旧私有内容。

商城、认证与消费者共享反馈组件没有修改。没有替换后端、改变合同或升级工具链。

七类表面为素材目录、新建素材、文字编辑、订单目录、订单详情、人工录入、CSV 页面。首个 fixture 的全部前后图片保留；最后增补的错误返回事件不改变这些静态界面，单独在新 fixture 留下三类本地返回及权限恢复重新鉴权的证据。

47 项覆盖：操作错误 RED/GREEN、筛选/返回/分页/空态、旧结果等待和禁用、503 保留与403隐藏、图片404回退/重试、素材冲突草稿、订单详情恢复/确认门禁、商品选择/人工表单输入保留、CSV 必须预演、初始加载/失败、宽窄屏/焦点/减少动态、对比度、普通成员与退出、三类同路由恢复及访问拒绝后重新鉴权。

503/403/409通过限定本机 TEST Fetch 请求的响应注入；素材 PATCH 和人工订单 POST 在进入 API 前被拦截，没有实际业务写入。图片测试只在 TEST 读取响应中为封面设置合法文件路径，实际文件 API 返回404；视频仅检查原生控件和不预加载，没有真实文件播放/存储证据。普通成员403和退出401使用实际 API，分别记录，不把模拟响应算成真实身份验证。

## 尝试、限制与保全

- [pre-final-build-checks](attempts/pre-final-build-checks.json)：静态测试服务仍在使用加入最后确认清理前的构建，首次恢复确认检查失败。重新构建后完整重验，最终确认状态为 false，未隐藏该尝试。
- [preview-network-observation](attempts/preview-network-observation.json)：首轮没有开启 Network 事件，只观察到预览回退；开启后重验实际404响应。
- [initial-request-cancellation](attempts/initial-request-cancellation.json)：初始导航取消早期 Fetch 请求，第一次注入没有在断言期限内作用于有效请求；改为逐波处理实际请求，最终取得真实503响应及恢复界面。
- [browser-cleanup-api](attempts/browser-cleanup-api.json)：浏览器不支持 `Storage.clearDataForOrigin`。已先实际退出账户，再仅清理唯一 TEST 来源可访问的 Storage/cookie 并关闭自建页签，没有清整个浏览器。

手机/平板是桌面浏览器视口模拟；SupabaseAuthGateway 使用已有协议替身，不能代替真实 Supabase/外部邮件/公网/真机。没有生成正式内容、上传媒体、发码、补发、CSV 预演/导入、退款、真实账号变更或云部署。

[源码摘要](verification.json)固定本批十份实现/测试文件；消费者、后端/合同、锁文件与 CI 工作流相对基线无差异。原未跟踪文件 `orai@0.1.0`、`pnpm` 保留。没有改写任何已封存的旧 `output` 证据。当前提交的托管 CI 需以实际推送 run 的最终状态为准，不能由本地通过推定。
