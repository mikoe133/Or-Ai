# 商品能力声明与内容工作台适配 · 本地验证

日期：2026-10-23。用户同意后实施；截图为自主验证，不作为用户逐页批准。

## 实现范围

- 工作台分为商品内容、体验设计、结果交付。内容版本明确注明单选 v1，保留 `tab=assessment/experience` 深链接、固定引用、来源和历史。
- 题目/结果文案共用内容草稿，场景/结果呈现共用体验草稿。页签切换保留输入；内容未保存时暂停体验审核和演示结果，避免将已保存结果误认为当前草稿结果。
- `experience.ts` 的注册表统一输入/评估/结果协议、编辑器、形式/参与条件、模板配对和预算；目前仅 DOM 单选/兼容图文和 2.5D 小屋/手记。
- `ProductCapabilitiesSchema` v1 是只读能力投影，不是发布、运行或权益授权。`basis` 区分共同设定与具体内容版本，`profileBinding` 区分固定/候选/未选设定。
- 工作台 API、四领域及 experience MCP 显式 `includeCapabilities:true` 后发现能力。旧默认响应及 `includeTemplates:true` 保持兼容。宣传领域没有新增私有评分、完整报告或消费者数据权限。
- 未实现形式的新内容编辑器保持待开发，已有单选内容只读保留。日志/书信等旧叙事方案仍可保存，原结构化内容与标准结果可以维护，方案不会自动启用新的结果模板。
- 体验审核/发布及没有体验草稿的默认发布路径检查对应能力；历史已发布版本和报告读取保持既有规则。
- 本轮未增加数据库迁移、依赖或新的商城视觉改动，未实现 Three.js、剧情/关卡引擎、多人或无评估交付。

## 实际浏览器检查

使用单独隐藏标签和现有本地管理员登录，用户原标签没有被导航。只修改浏览器内未保存草稿；题干、解释、模板和形式测试后全部还原，最终显示“无未保存修改”。未保存商品修改、发布商品或更改管理员权限。

1. 原 `tab=assessment` 链接进入商品内容；结果解释和公开样例在结果交付，场景/资源在体验设计。
2. 题干与报告解释分别修改后跨入口返回，两个值仍保留；隐藏编辑器继续挂载，版本/设定选择器在有草稿时锁定。
3. 安静小屋选择后，结果页呈现为小屋手记；返回体验页仍保留选择。随后恢复 DOM 组合，未保存该测试选择。
4. 创作设定临时选择 3D，界面明确显示“方案，待运行端支持”，然后放弃设定修改。未创建已保存的 3D 商品；未支持形式的新版本禁用/只读分支由共享模型及真实 API 测试覆盖。
5. 默认 1280×720：外层文档高度 720、后台工作区高度 668/可滚动内容高度 3380；横向页面宽度 1280。
6. 390×844：外层页面宽度 390、高度 844，后台工作区高度 792/可滚动内容高度 5482；选中结果页签可见，无整页横向溢出。结束恢复 1280×720。
7. 所有临时请求拦截已清除；没有把模拟响应或接口故障当作新商品的运行证据。
