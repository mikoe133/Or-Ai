# meetmyworld 后台设计画册

2026-10-20。围绕现有紫色品牌，重新组织后台的信息密度、导航、列表和编辑区。本次交付范围是 **32 个后台页面／关键工作状态 × 4 种风格，共 128 个精确中文设计画面**，并附 **4 张生成式风格参考图**、128 条逐页提示词和可滚动的浏览器设计稿。

这是设计评审材料。所有名称、数值、记录、预览和状态均为示例；设计中出现的布局与入口不代表新增业务功能已经实现。设计稿不连接业务 API，本次不修改业务代码。按钮仅用于展示操作位置，不能签发凭据、保存资料、发布商品或影响订单。

## 怎样查看

先打开 `index.html` 设计画册，按页面比较 A／B／C／D，查看设计图、完整页面及对应提示词。网页使用 ES module 和本地 JSON，建议通过附带的静态服务浏览，而不是直接双击 HTML。

在此目录启动：

```sh
node serve.mjs
```

也可以在仓库根目录启动：

```sh
node output/design-review/admin-redesign-20261020/serve.mjs
```

打开终端打印的本地地址，再进入 `index.html`。服务器只提供设计文件，不启动或修改业务后端。

`screen.html` 为可滚动的高保真页面。其参数是 `page` 和 `style`，例如：

```text
screen.html?page=skills-assessment&style=d
screen.html?page=content-video&style=b
```

每个逐页方案同时提供首屏 PNG 和完整长图：首屏用于比较构图，长图用于一次查看该方案的全部内容。进入完整页面后，也可以滚动查看首屏以下的表单、正文和记录。设计稿保持侧栏与顶栏固定，**只有右侧运营工作区上下滚动**。主导航只有一套，当前模块有明确选中状态；商品内容和 skill 领域使用二级导航。

## 四套方向

| 方向 | 视觉与布局 | 适合的工作 |
| --- | --- | --- |
| **A · 纸感编辑紫** | 暖白纸面、深紫墨色、细线；连续文档与旁注信息 | 长文、报告、创作规则、审核阅读 |
| **B · 精密工具紫** | 冷炭灰与淡紫、高密度分栏、精确对齐 | skill、MCP、版本、调用与审计 |
| **C · 柔雾创作紫** | 浅紫外壳、白工作面、舒展的列表与详情 | 内容制作、媒体、参考资料 |
| **D · 深茄夜间工作台** | 暖深紫、高对比、稳定工作区与底部操作栏 | 全后台日常运营、成套内容管理 |

**建议优先用 D 作为全后台方向**，最延续 meetmyworld 现有深色紫色品牌；借鉴 B 在 skill、MCP、审计等复杂页面中的密度与分栏方式。A、C 是浅色探索选项，并非默认把现有站点改成浅色。

四个方向应比较字体、留白、信息组织和操作位置，不只比较颜色。最终落地应统一导航、状态含义和组件规则，避免把四套装饰随意拼在一起。

## 页面范围

覆盖现有 7 个后台导航入口：概览与审计、商品与版本、内容工作台、素材与文件、skill 库、MCP 连接、订单与售后。

32 个设计覆盖单元包括：商品列表与详情、内容工作台的全部 10 个内容页签、素材列表与详情、四领域 skill 库各自的列表与编辑器、MCP 列表／创建／调用记录、订单列表／录入／CSV／售后，以及管理员访问状态。部分原页面中的列表、详情、表单被拆成独立设计状态；**不表示要增加 32 个正式路由**。

详细来源、范围和每页业务约束见 [page-inventory.md](page-inventory.md)。

## 继续开发时的依据

- 保留实际业务边界：已启用／归档 skill 版本只读，通过复制新版本继续编辑；内容采用不等于商品发布；MCP 不能越权发布或处理资金。
- 长 ID、摘要和原始 JSON 放入可展开详情；日常工作优先看到名称、版本、状态和内容。
- 紫色主要用于品牌、选中、聚焦与一个高优先级主操作。状态同时显示文字，不依赖颜色识别。
- 保留后台内容区独立滚动与明确的当前导航状态；避免恢复前台与后台的重复导航。
- 不把图中的筛选、拖拽、布局分区或辅助操作直接视为已实现功能。实施时逐页与现有 API、状态流转和权限校对。
